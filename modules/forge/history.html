锻造历史记录 ​

Forge 按玩家保存锻造记录，用于统计配方使用次数、驱动品质保底计数和支撑锻造相关占位符。

配置位置 ​

历史记录位于 config.yml 的 history 节点：

yaml
history:
  enabled: true
  auto_save: true
  # 自动保存间隔，6000 tick = 5 分钟
  save_interval: 6000

字段说明 ​

字段类型默认值说明
enabledbooleantrue是否启用锻造历史记录。
auto_savebooleantrue是否定时保存玩家数据。
save_intervalinteger6000自动保存间隔，单位 tick。6000 tick 约为 5 分钟。

NOTE

enabled 与 auto_save 任一为 false 时，定时自动保存任务不会被调度。

存储位置 ​

玩家数据保存在 plugins/EmakiForge/data/<玩家UUID>.yml，每名玩家一个文件。

记录内容 ​

每个玩家文件按配方 ID 记录：

信息用途
玩家 UUID文件名与文件内 uuid 字段，定位数据归属。
配方 ID按配方分组记录锻造数据。
锻造次数支撑 %emakiforge_craft_count_<recipe_id>% 与总次数统计。
最后锻造时间字段 last_crafted_at，支撑 %emakiforge_last_crafted%。
保底计数品质保底的连续计数，按玩家 + 配方维度记录。

与品质保底的关系 ​

保底计数器就保存在玩家数据文件中，两者直接相关：

  • 每次锻造结果低于保底最低品质时，保底计数 +1。
  • 计数达到阈值后触发保底，并重置计数。
  • 保底触发条件与阈值见品质系统。

使用建议 ​

  • 正式服建议开启 enabled 和 auto_save。
  • 高并发服务器可适当提高 save_interval，减少频繁写盘。
  • 赛季服或活动服可以在活动结束后归档 data/ 目录，用于统计配方产出。

排查建议 ​

  • 数据未保存：检查 enabled、auto_save 和 data/ 目录权限。
  • 玩家数据加载失败时，该玩家会话会保持只读以保护已有文件，控制台会输出对应警告。
  • 保底表现异常：先用 %emakiforge_guarantee_<recipe_id>% 确认当前计数，再核对配方与全局的保底配置。
  • 重载后数据异常：确认自动保存间隔，必要时在维护前先停服等待数据落盘。
