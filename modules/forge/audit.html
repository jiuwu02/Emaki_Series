审计与签名 ​

Forge 在锻造成功后会向结果物品写入审计数据，用于追溯锻造来源和防篡改验证。

数据落在哪里 ​

锻造审计数据同时存在于两个位置：

  1. CoreLib 物品层快照：namespace 为 forge，layer version 为 1，payload 就是下面的审计字段表（由 ForgeLayerSnapshotBuilder 组装）。刷新物品时从这里读回。
  2. emakiforge:forge PDC 分区：把关键字段打成扁平键，供占位符与变量系统读取。见锻造层 PDC 键。

审计字段 ​

锻造完成后，以下字段写入审计 payload：

字段说明
schema审计结构标识，当前固定为 forge_audit_v2。
schema_version审计结构版本，当前为 2。
stage来源阶段，当前固定为 forge。
recipe_id使用的配方 ID。
quality品质等级名称；品质未解析时为空字符串。
multiplier品质倍率。
forged_at锻造时间戳（毫秒）。
materials_signature材料贡献数据的稳定哈希签名。
output_item输出物品来源简写。仅在配方配置了输出物品来源时写入。
materials材料贡献列表，见下表。

materials[] 每个条目的字段：

字段说明
material_id / count_key / audit_id材料身份键。仅在配置里显式声明过时写入；未声明时该键被移除。
material_item兼容身份：物品源简写，或 matcher:<摘要>。
category材料分类（必需 / 可选）。
amount规划投入的数量。
amount_consumed实际消耗的数量。
slot材料所在的 GUI 槽位。
sequence处理顺序。
matched_source实际匹配到的物品源简写。
matchermatcher 摘要键；没有 matcher 时为空字符串。
allocation该条目的槽位分配明细。
legacy_identity / identity_diagnostic存在未显式声明的身份键时补充的兼容身份与诊断标记。

材料签名 ​

materials_signature 只对实际消耗数量大于 0 的材料贡献计算稳定哈希签名，签名输入包含材料定义摘要、数量、消耗量、槽位、分类、顺序、匹配来源与分配明细。相同的材料贡献组合总是得到相同签名，因此可以用于比对物品的锻造材料数据是否与预期一致。

锻造层 PDC 键 ​

命名空间 emakiforge、分区 forge 下的扁平键：

键类型说明
forge_recipe_idstring锻造该物品的配方 ID。
quality_idstring品质 ID（与品质名同值）。
quality_displaystring品质显示名。
quality_multiplierstring品质倍率，按 0.## 格式化后存储。
material_idstring显式声明的 material_id 列表，逗号连接；无则移除该键。
count_keystring显式声明的 count_key 列表，逗号连接；无则移除该键。
audit_idstring显式声明的 audit_id 列表，逗号连接；无则移除该键。
matched_sourcestring匹配来源简写列表，逗号连接。
amount_consumedinteger全部材料实际消耗量合计。
matcher_digeststringmatcher 摘要列表，逗号连接。
allocationstring分配明细的稳定签名。

这些键会被 CoreLib 变量系统读取为 forge_quality_id、forge_quality_display、forge_quality_multiplier、forge_recipe_id 四个变量。

与刷新的关系 ​

Forge 的物品刷新服务会读取审计数据中的 recipe_id 和 quality，据此重建锻造层展示。审计数据缺失、品质已不在当前品质池中，或配方已被删除时，对应物品无法重建锻造层展示并会打警告。

读取材料审计记录时，当前实现按 audit_id → material_id → count_key → 旧 material_item / source 依次回退。使用旧身份成功解析后会标记为需要迁移并在刷新时重建；身份全部无法解析时保留原物品并记录 warning，不会用不完整结果覆盖原状态。材料身份键必须保持稳定：纯 matcher 材料会按 matcher 内容摘要派生身份，改动 matcher 后旧成品会报「未找到材料」（console.forge_refresh_missing_material）。该行为已由源码证明，但本轮没有在真实 Paper/Folia 服务器上验证旧 PDC 审计数据。

用途场景 ​

  • 交易或回收系统可读取审计数据判断物品的配方来源与品质。
  • 外部统计可按 recipe_id、quality 和 forged_at 聚合锻造产出。

NOTE

Forge 未提供查看审计数据的内置命令。需要人工查看时，请使用支持读取物品 PDC 与物品层快照的外部工具。
