命令与权限 ​

EmakiForge 的全部命令和权限节点, 以及每种场景先执行哪条命令

EmakiForge 的主命令是 /emakiforge, 别名 /eforge, /ef. 玩家用它打开锻造界面或配方书, 管理员用它重载配置, 列出配方和查看运行状态

命令列表 ​

主命令本身需要 emakiforge.use (默认 true). 子命令的额外权限如下表

命令说明权限
/ef help显示这份帮助. 直接执行主命令不带参数时, 效果相同仅需主命令权限
/ef forge打开锻造界面. 只有玩家能执行, 在控制台执行会提示仅玩家可用仅需主命令权限
/ef book打开配方书. 只有玩家能执行, 在控制台执行会提示仅玩家可用emakiforge.book 或 emakiforge.admin
/ef list <type>列出已经加载的配置和它们的显示名. 目前只支持 recipe (写 recipes 也认), tab 补全只会提示 recipe; 填其他值会返回参数错误emakiforge.admin
/ef reload重新加载配置, 语言, GUI 模板和配方, 完成后回报重载了多少条配方, 多少个 GUI 模板, 以及花了多少时间emakiforge.reload 或 emakiforge.admin
/ef convert-legacy [confirm]把 recipes/ 里 materials[], blueprint_requirements[] 和 result.*.outputs[] 的旧 item_sources 写法迁移过来; 材料项按规格保留旧键. 不带参数只预演, 不写文件; 带 confirm (或 --apply) 才真正写文件, 并保留一份 .bak 备份emakiforge.admin
/ef debug stats输出运行时的各项指标和配方加载报告 (写 status 效果一样)emakiforge.debug 或 emakiforge.admin
/ef debug on / off总开关, 打开或关闭全部调试输出emakiforge.debug 或 emakiforge.admin
/ef debug player <玩家>只跟踪某一个玩家的调试输出emakiforge.debug 或 emakiforge.admin
/ef debug module <模块>打开某一个子模块的调试输出emakiforge.debug 或 emakiforge.admin

调试子模块可以填 recipe, forge, gui, pdc. /ef debug 下其余参数交给 CoreLib 的调试命令处理

别名 eforge, ef 与主命令的行为完全一致

权限节点 ​

权限默认说明
emakiforge.usetrue使用主命令和锻造界面
emakiforge.booktrue打开配方书
emakiforge.reloadop重载配置
emakiforge.debugop输出调试信息
emakiforge.adminop管理员权限

先用哪个命令 ​

场景先执行目的
玩家要锻造装备/ef forge打开锻造界面
玩家找不到配方/ef book查看配方有没有加载
管理员改了配方或 GUI/ef reload重新加载 recipes/, gui/, 语言和运行时资源
不确定配方是否加载/ef list recipe查看当前加载了哪些配方
配方加载有告警或异常/ef debug stats查看运行时指标和配方加载报告
锻造结果异常/ef debug module forge打开 forge 子模块的调试输出

使用场景 ​

玩家打开锻造界面 ​

text
/ef forge

你把图纸放进图纸槽后, Forge 按图纸的物品来源匹配配方, 然后依次做条件检查, 容量检查, 材料检查, 品质计算和结果生成

玩家查看配方书 ​

text
/ef book

配方书分页展示已经加载的配方. 你在配方书里看不到某个配方时, 先用 /ef list recipe 确认它有没有加载

管理员重载 ​

text
/ef reload

你改过 recipes/, gui/ 或语言文件之后就用它. 重载成功会回报重载的配方数与 GUI 模板数. 调试配方时, 建议你重载前先备份正在改的那份配方文件
