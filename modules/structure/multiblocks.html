多方块结构 ​

多方块结构定义存放在 plugins/EmakiStructure/multiblocks/<id>.yml. 玩家通过交互 (右键等) 凑齐形状后, 插件校验通过即触发该定义的 trigger.actions 动作行

定义格式 ​

yaml
version: 1                    # 当前仅支持 1, 过旧报 version_outdated, 过新报 version_unsupported
id: "teleporter"              # 必须与文件名一致, 否则拒载 (id_mismatch)

shape:
  allow_rotation: true        # 默认 true, 是否允许旋转匹配
  core_block: [4, 1, 4]       # 可选: 核心方块相对坐标 (触发锚点)
  blocks:
    - pos: [4, 1, 4]
      block: "minecraft:obsidian"
    - pos: [4, 2, 4]
      block: "minecraft:ender_eye"       # 带方块状态用 minecraft:...[state=value]
    - pos: [5, 1, 4]
      block: "craftengine-myns:console"  # 自定义方块: 来源-原始id, 不允许携带状态段
    - pos: [6, 1, 4]
      furniture: "itemsadder:myplugin:chair"  # 家具成员, 与 block 二选一

trigger:
  targets: "any"              # any (任意成员) / specific (positions 指定) / all (全部成员)
  positions:                  # targets=specific 时必填
    - [4, 1, 4]
  actions: |                  # 逐行执行的 CoreLib 动作管道行
    send_message "&a传送门已激活！"
    action giveexp amount=10

cooldown:                     # 可选
  global: "0"                 # 同结构跨玩家共享; 0 = 无冷却, 支持 30s/5m 后缀
  per_player: "0"             # 单玩家单结构计时

condition: "permission=teleport.use"   # 可选: 触发前置条件 (CoreLib 条件语法, 见 CoreLib 条件系统页)

校验规则 (任一不通过即拒载或跳过该条, 均带文件与条目序号回显):

  • 每条成员必须且只能声明 block 或 furniture 之一; 坐标非负, 在尺寸内且不重复
  • furniture 前缀限 itemsadder: / oraxen: / nexo: / craftengine:
  • block 为 minecraft: 时可用方块状态; 非原版前缀视为自定义方块 id, 不允许携带状态段
  • targets 非 any/specific/all, specific 缺 positions, 无有效成员 (blocks_empty) 等均为整文件拒载
  • id 与文件名不一致, version 不为 1, 解析失败同样拒载
  • 同 id 重复定义时后者不加载 (duplicate_id)

命令 ​

  • /ems multiblock export <id> [force]: 按当前选区导出布局; id 已存在需 force 覆盖 (already_exists)
  • /ems multiblock place <id> [朝向]: 手工放置 (原版方块 / 自定义方块 / 家具三类成员), 完成后触发形成检测登记; 失败条目最多回报 5 条
  • /ems multiblock list: 列出定义与实例统计
  • /ems multiblock validate <id>: 对现场形状做一次校验, 未通过则该实例降级为未完成 (verification_failed)

触发流程 ​

  1. 玩家交互命中结构区域 (或点击候选锚点)
  2. 形状增量检测判定是否"凑齐": 同区块变更合并去抖 (detection.debounce), 冷命中反推锚点受 detection.max_cold_checks 预算限制
  3. 通过 condition 条件 (以 CoreLib 条件组求值, 整组不满足即不触发) 与冷却检查 -- 冷却取定义自带 cooldown 节, 未声明时回退 config.yml 的 cooldown.global / cooldown.per_player
  4. 同步发布 MultiblockTriggerEvent (不可取消, 在处理交互的线程上触发; Folia 上为点击方块所属 region 线程)
  5. 执行 trigger.actions 动作行 (走 CoreLib 动作管道)

retrigger_on_reform: false (默认) 时, 结构被破坏后重新凑齐只恢复为活动实例, 不重复触发, 防止刷动作

增量检测配置要点 ​

见配置详解的 detection 节: sweep_interval (低频兜底巡检, 0 关闭且启用时须 ≥ 30s), instance_limit (每定义每玩家进行中实例上限), instance_ttl (无变化实例存活时长), sample_recheck (活动实例低频抽样复验, 默认关闭)
