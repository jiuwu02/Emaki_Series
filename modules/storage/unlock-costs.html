付费扩容档位 ​

unlock_costs.yml 定义 GUI 内付费扩容的价格档位。这是独立的业务数据文件：release_default_data 只在文件缺失时释放一次，版本升级不会覆盖管理员已有内容。

文件名由 config.yml 的 unlock.cost_file 指定，默认 unlock_costs.yml；是否开放购买由 unlock.purchase_enabled 与 emakistorage.unlock.purchase 权限共同决定，见配置详解。

unlock_costs.yml 结构 ​

yaml
tiers:
  - count_range: "1-9"
    currency:
      type: vault
      amount: 1000
  - count_range: "10-19"
    item:
      source: "diamond"
      amount: 16
  - count_range: "20-49"
    currency:
      type: vault
      amount: 50000
    item:
      source: "netherite_ingot"
      amount: 4

fallback:
  currency:
    type: vault
    amount: "100000 * 1.05 ^ (%count% - 50)"
  max_amount: 1000000000

batch:
  enabled: true
  options: [1, 5, 10, 64]
字段类型必填默认值取值范围说明
tierslist<map>否见示例（3 档）每个元素为下表的键集付费档位列表。count_range 非法或两种价格都缺的档会被整档跳过并记 warning。
tiers[].count_rangestring是—（无该键的档被跳过）"N" 或 "min-max"；要求 min ≥ 1 且 max ≥ min该档覆盖的「第几格」区间，如 1-9。越靠前的档优先。
tiers[].currencysection否发货档位部分含此项见下方三行货币代价。与 item 至少要写一个，否则该档被跳过。
tiers[].currency.typeenum否vaultvault / excellent货币后端 id，未知值回退 vault。
tiers[].currency.currencystring否""（空）后端自身的货币标识传给经济后端的货币 id；留空表示使用该后端的默认货币。发货文件未写此键。
tiers[].currency.amountnumber 或 string是（写了 currency 时）—非负数，或可被表达式引擎求值的字符串金额。数字直接使用；字符串走 CoreLib ExpressionEngine，可用 %count%。既不是数字也不是非空字符串时，该 currency 段视为未配置。
tiers[].itemsection否发货档位部分含此项见下方两行物品代价。
tiers[].item.sourcestring是（写了 item 时）—CoreLib ItemSource token缺失或为空白时该 item 段视为未配置。
tiers[].item.amountint否1（缺省或非数字时）> 0；≤ 0 时该 item 段视为未配置所需物品数量。
fallbacksection否见示例见下方三行兜底档：超出所有 tiers 后的每一格价格。
fallback.currencysection否见示例键集同 tiers[].currency兜底档的货币代价。
fallback.itemsection否无键集同 tiers[].item兜底档的物品代价。fallback 下两种价格都缺时不生效。
fallback.max_amountnumber是（要用兜底档时）—> 0单格价格上限。缺失或非正数时兜底档整体失效，超出 tiers 的格子不可购买。
batchsection否enabled: true、options: [1, 5, 10, 64]见下方两行批量购买选项。
batch.enabledboolean否truetrue / false为 false 时一次点击固定购买 1 格。
batch.optionslist<int>否[1, 5, 10, 64]只接受正整数元素；过滤后为空则回退默认值一次点击可购买的格数选项。当前 GUI 只取列表第一项：点击扩容按钮固定购买 options[0] 格，其余选项在本模块内没有入口，保留它们只是预留能力。

逐格计价 ​

批量购买按逐格计价再求和结算，不是「单价 × 数量」。玩家购买第 N 格时，用 N 落在哪个 count_range 决定该格价格；N 从 purchasedSlots + 1 开始递增。若按当前单价乘以数量，玩家可以在最便宜的档一次买下大批槽位，把本该属于昂贵档的格子锁定成低价。发货默认 batch.options: [1, 5, 10, 64] 且 GUI 只取第一项，所以实际下单通常只有 1 格，逐格求和退化为单格报价；把 options[0] 改成较大值即可一次购买多格，此时才真正体现逐格累加。

%count% 在表达式中表示「即将购买的第几格」。无档位命中时用 fallback。

示例：1–5 格用金币，之后每格用钻石，并放开一次买 10 格。

yaml
tiers:
  - count_range: "1-5"
    currency:
      type: vault
      currency: "coin"
      amount: 500

fallback:
  item:
    source: "diamond"
    amount: 2
  max_amount: 100000

batch:
  enabled: true
  options: [10]

max_amount 护栏 ​

fallback.max_amount 是必需项：缺失或非正数时兜底档整体失效，超出 tiers 的格子将不可购买（回报 no_price_defined）。它的作用是防止指数表达式溢出成 Infinity。

护栏只作用于兜底档：命中 tiers 的格子不受 max_amount 限制，它们只受「金额必须有限且非负」这一条约束（违反时报 price_overflow）。

当某一格的计算价格超过 max_amount 时，实现明确拒绝本次报价（price_over_cap），而不是静默钳到上限：管理员的公式产出了越过自己声明的护栏的价格，这次购买就不该继续。

购买入口与前置校验 ​

当前付费扩容只有 GUI 一个入口：点击 unlock 按钮。点击前依次校验

  1. unlock.purchase_enabled 为 true，否则回报「未开放」。
  2. 玩家持有 emakistorage.unlock.purchase，否则回报无权限。
  3. unlock_costs.yml 提供了可用档位或可用兜底档，否则 no_price_defined。
  4. 本次购买不会突破 capacity.max_slots（effectiveSlots + 购买格数 > max_slots 时回报 max_slots_reached）。

订单格数取自 batch.options 的第一项，见上文 batch.options 说明。

支付顺序与逆序补偿 ​

购买流程：报价 → 触发可取消的 StorageUnlockEvent → 扣货币 → 扣物品 → 增加 purchasedSlots。

任何一步在扣款之后失败，都会按逆序补偿：先按倒序回滚已应用的物品扣除计划，再退还货币，然后才返回失败。purchasedSlots 在补偿路径上从未被修改过。

失败采用 fail-closed：没有匹配档位且没有可用兜底档时拒绝购买，而不是当成免费。
