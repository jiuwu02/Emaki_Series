EmakiDungeon ​

EmakiDungeon 是一款组队副本玩法插件: 你和队友组好队伍, 选好难度, 一起进入一份专属的副本世界打通关拿奖励

  • 每支队伍挑战时都会拿到一份从模板克隆出来的独立世界, 不同队伍互不干扰, 打完立即销毁
  • 副本自带完整的挑战流程: 先选难度与掉落分配模式, 再做准备确认, 等世界准备倒计时结束, 就能进入副本
  • 次数限制按 日 / 周 / 月 三层管理, 支持可挑战时段, 周几, 月周次与冷却
  • 局内走分配的奖励先进入暂存区, 通关才发放; 中途退出或挑战失败则全部作废, 玩家状态按进入前的快照回滚
  • 自带队伍系统 (邀请/申请/踢人/队伍频道), 副本内聊天默认与外界隔离, 你随时可以切回全局收听
  • 内置地图编辑器: 你在游戏里圈选区域, 放标记, 填方块, 测试开局, 保存后直接回写模板
  • 流程由 flow.yml 描述: 房间, 波次, 门禁, 分支选项, 触发区, 计时, 击杀目标等 22 类功能模块
  • 支持 GraalJS 副本脚本与 CoreLib 动作管道, 你可以按副本生命周期挂自定义逻辑

默认配置目录 ​

text
plugins/EmakiDungeon/
├── config.yml               ← 主配置 (全局开关与限流)
├── world/
│   └── <副本ID>/
│       ├── config.yml       ← 副本配置 (缺失时按模板自动生成)
│       ├── flow.yml         ← 流程定义 (缺失时按模板自动生成)
│       └── region/          ← 副本地图的区块存档
├── gui/
│   └── rewardbox.yml        ← 奖励箱界面 (页数与容量)
├── scripts/                 ← 副本 GraalJS 脚本, 文件名 = <副本ID>.js (可选)
├── instances.yml            ← 运行时实例记录 (自动生成, 不要手改)
├── parties.yml              ← 队伍快照 (自动生成, 不要手改)
└── lang/

副本模板就是 world/ 下的一个文件夹, 文件夹名就是副本 ID. 插件在启动和执行 /edg admin reload 时扫描该目录, 缺 config.yml 或 flow.yml 会自动按内置模板补上, 已有的不会被覆盖

典型工作流 ​

  1. 先在 plugins/EmakiDungeon/world/ 下新建一个文件夹当作副本 ID (例如 my_dungeon), 把你的地图区块放进其中 (或先建空目录, 用编辑器搭)
  2. 重启服务器或执行 /edg admin reload, 缺失的 config.yml 与 flow.yml 会自动生成
  3. 执行 /edg editor my_dungeon 打开编辑器, 圈区域, 放标记, 搭流程; 改完点"保存并回写模板"
  4. 再手工调 config.yml 里的难度, 次数限制与掉落分配, 调完再次执行 /edg admin reload
  5. 玩家用 /edg list 看有哪些副本, 用 /edg enter my_dungeon 发起挑战; 队长选难度, 全员准备后进入
  6. 打完开箱领奖 (/edg rewards), 或在配置里关掉奖励箱让产出直接进背包

与其他模块的关系 ​

模块协作方式
EmakiCoreLib必需依赖: 调度, 消息, 配置检查与动作管道; 副本生命周期动作由 CoreLib 的动作段执行
EmakiMobs流程刷怪点可用 emakimobs: 前缀引用 EmakiMobs 生物定义 (不装则只能用原版实体)
EmakiItem / EmakiLevel副本结算命令 settlement.commands 里可以直接调它们的命令发物品与经验
MythicMobs / WorldGuard可选依赖, 未安装时插件正常运行, 对应联动停用
