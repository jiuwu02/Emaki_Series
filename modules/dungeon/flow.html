流程与触发器 ​

flow.yml 是副本的"玩法图纸": 房间怎么推进, 怪分几波, 门什么时候开, 玩家做选择后走哪条路, 全写在这个文件里. 它位于 plugins/EmakiDungeon/world/<副本ID>/flow.yml, 缺失时插件按内置模板自动生成. 模块 ID 在副本内必须唯一, 加载期会校验重复与越界定义; 加载失败时该实例回退为空流程, 你可以用 /edg admin validate 提前体检全部模板

绝大多数人不需要手写它: 用 地图编辑器 在游戏里放标记, 点保存就会写进 flow.yml. 生成出来的结构, 以及怎么用条件和动作把它们串起来, 说明如下

文件骨架 ​

内置模板长这样 (真实文件节选):

yaml
version: "1.0.0"

rooms: {}

入口点约定: 新建副本一律不要在 flow.yml 写 spawn_point 覆盖节 (内置默认模板已移除该节), 入本点统一回退到世界出生点. 你要用 /setworldspawn 把模板世界出生点设置到净空落点, 并保证模板 level.dat 中的出生点有效 (服务端加载时会校验存储的出生点, 无效则会重新选定别的位置). 模板导出后核对 flow 无该节, 再用一次真实进入核对实际落点. 依赖入口位置的区域模块 (如 entry_timer 的 region) 必须覆盖实际落点. spawn_point 仍可作为显式覆盖项使用, 写入后入本/重生/结算落点全部以它为准

每个模块都是"节名 → { 模块 ID → 模块内容 }"的两层结构, 模块内容里带自己的 id 与 enabled 开关, 例如实测副本里的一条房间计时:

yaml
room_timers:
  entry_timer:
    id: entry_timer
    enabled: true
    region:
      min:
        x: -20.0
        y: 55.0
        z: -20.0
      max:
        x: 20.0
        y: 80.0
        z: 20.0
    seconds: 15
    on_zero:
      type: complete
      cause: timed

这条的含义: 玩家进入该区域后开始 15 秒倒计时, 到零执行 complete 动作结束本局. 区域 (region) 一律用 min / max 两个对角坐标表示

分支选项与结局 ​

options 节用来定义玩家面前的分岔路, 玩家的交互过程全部走聊天栏:

  1. 触发后发提示"请选择: ... (输入序号或标识)"
  2. 再做二段确认: "已选 ... 输入 确认 定案, 超时自动定案, 输入 取消 放弃"
  3. 数量必须落在 min_select~max_select 之间, single 单选 / multi 多选
  4. time_limit_seconds 是选择时限, 0 不限; 超时未选视为放弃

选中的候选项 (cases) 带自己的 label 显示文本, ending 结局 id, 以及 seal_regions 封路区域: 落选的路会被封住, 玩家靠近封路区会被拉回该候选项的 safe_point 安全点. 多个候选项的结局经 ending_map 组合成最终 ending. 选项弹出选择提示前触发 DungeonChoiceEvent (可取消, 取消则不发提示), 定案后触发 DungeonOptionConfirmEvent, 封路触发 DungeonSealPathEvent, 收尾触发 DungeonEndingEvent (事件清单见 API 与集成)

地图编辑器 ​

用 /edg editor <副本ID> (需 emakidungeon.editor) 进入独立编辑世界后, 你可以这样做:

  1. 放标记: 单点标记 (spawn/option/chest) 对准方块直接记, 区域标记 (room/gate/trigger) 用 pos1 + pos2 圈两点; marks 查看暂存列表
  2. 改配置: 主面板分四块 — 副本元数据, 刷怪点与波次, 门禁, 分支选项; 字段改完先暂存
  3. 搭地形: fill <方块> 对圈选区域分帧填充
  4. 测试: test 按已保存的模板走一遍正常进入流程, 不计次数, 不上榜; 有未保存改动时会被拒绝
  5. 保存: 点"保存并回写模板"把标记与面板改动写进 config.yml / flow.yml 并回写地形, 回显新的世代号; exit 退出, 未保存的改动会全部丢弃

同一副本模板同时只允许一个编辑会话; 你正处于副本实例或挑战流程中时无法打开编辑器, 需要先结束; 编辑世界残留会在插件启动时自动清扫

GraalJS 副本脚本 ​

scripts/<副本ID>.js 会随该副本的每个实例启动装载, 实例销毁即释放 (开关与超时见主配置 script 段). 你可以在脚本里:

  • dungeon.takeover() 接管整局推进, 之后由脚本节奏控制流程
  • onTrigger('onEnter', ...) / waitFor('onRoomEnter') 订阅与等待触发 (如 onEnter, onRoomEnter, onWaveClear, onRoomClear, onBossKill, onGateOpen)
  • dungeon.spawnWave(...) / dungeon.openGate(...) / dungeon.enterRoom(...) / dungeon.complete(...) 驱动流程
  • dungeon.registerEntry(...) 给全员登记临时词条 (实例结束自动摘除), dungeon.hint(...) 发提示
  • dungeon.factFlag(...) / dungeon.setFact(...) 在脚本自己的事实位之间传递状态

脚本异常或超时只会停用该脚本, 实例照常运行 (除非你把 script.fail-on-error 打开); 完整示例见插件资源里的 examples/example_flow.js. 三方插件也可以经 API 注册脚本触发器, 见 API 与集成
