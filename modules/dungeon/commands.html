命令与权限 ​

EmakiDungeon 的主命令是 /edg, 你也可以用别名 /dungeon 与 /edungeon. 玩家侧命令默认都开放 (emakidungeon.play 默认为 true), 管理与编辑器命令则需要对应权限

玩家命令 ​

命令说明所需权限
/edg help查看命令帮助 (无参数时等同于 help)emakidungeon.play
/edg list查看当前可用的副本列表emakidungeon.play
/edg enter <副本ID>发起挑战并进入副本; 组队状态下仅队长可发起emakidungeon.play + emakidungeon.dungeon.<副本ID>
/edg leave退出当前副本; 会先二次确认, 聊天输入 确认 退出, 输入 取消 放弃emakidungeon.play
/edg cancel取消进行中的进入等待或挑战流程 (准备窗口内任一队员可取消)emakidungeon.play
/edg ready准备确认窗口内确认就绪 (也可以点击弹出的确认按钮)emakidungeon.play
/edg rewards打开个人奖励箱领取通关奖励emakidungeon.play
/edg stats [玩家] [副本ID]查询进入次数 (日/周/月与冷却) 和最佳成绩emakidungeon.play
/edg rank <副本ID>查看该副本排行榜前 10 名 (分数, 用时, 难度, 队伍)emakidungeon.play
/edg globalchat <on|off>切换全局消息收听; on 后实例内外消息互通, off 时副本内消息只在实例内闭环emakidungeon.play
/edg editor <副本ID>打开地图编辑器, 进入该副本的独立编辑世界emakidungeon.editor

队伍子命令 ​

用 /edg party <子命令> 管理队伍:

子命令说明限制
create创建一支新队伍 (自己当队长)已在队伍中时不可再建
invite <玩家>自己有队伍: 邀请对方入队 (仅队长); 自己没队伍: 向对方发起加入, 按邀请模式处理有队伍时仅队长可执行
accept邀请的接收方用来接受邀请; 申请的接收方 (队长) 用来批准申请按收到的是邀请还是申请而定
deny拒绝收到的邀请 (被邀请者) 或拒绝入队申请 (队长)按收到的是邀请还是申请而定
kick <玩家>踢出队员仅队长
leave自己离队 (队长离队时移交给其他队员)—
disband解散整支队伍仅队长
chat切换队伍频道: 开启后你的消息只有队伍可见—

邀请模式由全局配置 party.invite-mode 决定, 它控制没队伍的玩家向别人发起加入时的结果: public 直接加入, apply 提交申请等队长批准, invite 只有被邀请的人才能加入 (其他值按 invite 处理); 队伍人数上限见 party.max-size

编辑器会话命令 ​

拥有 emakidungeon.editor 权限的玩家执行 /edg editor <副本ID> 后进入编辑会话, 可用子命令:

子命令说明
/edg editor pos1 / pos2记录区域的第一个 / 第二个角点 (站到目标区域的两个对角各记一次)
/edg editor mark <类型> [id]在视线 16 格内的方块上放一个标记, 暂存到会话, 保存后写入 flow.yml
/edg editor marks列出本会话已暂存的标记
/edg editor fill <方块>用 pos1 + pos2 圈出的区域批量填方块 (分帧写入, 有数量上限)
/edg editor test测试开局: 走正常进入流程, 不计次数, 不上榜; 必须先保存模板
/edg editor exit退出会话; 有未保存改动时会先拒绝, 要求保存或放弃

标记一共分两组:

类型记法用途
spawn / option / chest单点, 对准方块直接记出生落点 / 选项节点 / 奖励点
room / gate / trigger区域, 需要 pos1 + pos2房间 / 门禁封门区 / 触发区

编辑器的主面板 (元数据, 刷怪点与波次, 门禁, 分支选项) 通过 GUI 操作; 标记和面板改动都只是暂存, 你点击"保存并回写模板"后才写进模板文件; 未保存就退出会丢弃全部改动. 同一副本模板同时只允许一个编辑会话

管理命令 ​

用 /edg admin <子命令> 执行管理操作, 需要 emakidungeon.admin 权限 (默认 OP):

子命令说明
instances列出全部运行中的实例 (实例 ID, 副本, 状态, 队伍, 写队列积压)
stop <实例ID>强制结束指定实例
status运行状态总览: 实例数, 存活虚拟线程, 副本模板数, 各池占用与写队列
reload重载主配置与全部副本配置; 运行中的实例不受影响, 只对之后新建的实例生效
validate校验全部副本模板, 报告缺失 flow.yml 或配置非法的副本
poolreset <副本ID>强制重置该副本的池补位世界
clearslots清理残留的池占位记录

NOTE

reload 必须由拥有权限的玩家在游戏内执行, 控制台直接执行会提示"此命令只能由玩家执行". 想让假人或脚本重载时, 先给对应玩家 emakidungeon.admin 权限再执行

权限节点 ​

节点默认用途
emakidungeon.play所有玩家进入, 组队, 查询, 全局收听等玩家侧命令
emakidungeon.dungeon.*所有玩家全部副本的进入许可 (实际按每个 emakidungeon.dungeon.<副本ID> 逐个校验)
emakidungeon.bypass.limitOP绕过次数与冷却限制
emakidungeon.bypass.escapeOP逃逸防护豁免 (调试与维护用)
emakidungeon.scriptOP副本脚本装载与触发器注册
emakidungeon.editorOP地图编辑器会话
emakidungeon.adminOP实例管理, 强制结束, 重载, 池维护
emakidungeon.*OP以上全部的通配节点

emakidungeon.dungeon.<副本ID> 在插件启动与重载时按 world/ 下的副本目录动态注册, 默认所有玩家都能进; 副本被删除时对应节点一并移除. 想做"会员专属副本", 你在权限插件里把该节点的默认值关掉, 只授予指定组即可

副本内的命令限制 ​

进入副本后, 玩家发出的命令会依次过两道闸:

  1. 逃逸黑名单 (escape.blacklist, 支持通配符): 命中直接拒绝, 提示"该命令在本副本受限 (逃逸黑名单)", 这一层不可被任何放行条目豁免
  2. 命令管控 (commands.mode 为黑名单或白名单模式): 按全局 commands.rules 与副本级 commands.allow 判定, 拒绝时提示"该命令在本副本受限 (命令管控)"
