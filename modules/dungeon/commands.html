命令与权限 ​

EmakiDungeon 的主命令是 /edungeon, 短别名 /ed. 玩家侧命令默认都开放 (emakidungeon.play 默认为 true), 管理与编辑器命令则需要对应权限

玩家命令 ​

命令说明所需权限
/edungeon help查看命令帮助 (无参数时等同于 help)emakidungeon.play
/edungeon list查看当前可用的副本列表emakidungeon.play
/edungeon enter <副本ID>发起挑战并进入副本; 组队状态下仅队长可发起emakidungeon.play + emakidungeon.dungeon.<副本ID>
/edungeon leave退出当前副本; 会先二次确认, 聊天输入 确认 退出, 输入 取消 放弃emakidungeon.play
/edungeon cancel取消进行中的进入等待或挑战流程 (准备窗口内任一队员可取消)emakidungeon.play
/edungeon ready准备确认窗口内确认就绪 (也可以点击弹出的确认按钮)emakidungeon.play
/edungeon rewards打开个人奖励箱领取通关奖励emakidungeon.play
/edungeon stats [玩家] [副本ID]查询进入次数 (日/周/月与冷却) 和最佳成绩emakidungeon.play
/edungeon rank <副本ID>查看该副本排行榜前 10 名 (分数, 用时, 难度, 队伍)emakidungeon.play
/edungeon globalchat <on|off>切换全局消息收听; on 后实例内外消息互通, off 时副本内消息只在实例内闭环emakidungeon.play
/edungeon editor <副本ID>打开地图编辑器, 进入该副本的独立编辑世界emakidungeon.editor
/edungeon recruit <open|close|list|join>组队招募板: open <副本ID> [难度] 发布招募 (仅队长), close 关闭招募, list 查看进行中的招募, join <编号> 加入招募emakidungeon.play
/edungeon match <join|leave>本服自动匹配: join <副本ID> [难度] 加入匹配队列, leave 离开匹配队列emakidungeon.play
/edungeon spectate <next|prev>观战模式下切换观战目标 (下一个 / 上一个); 不在观战模式时提示emakidungeon.play

招募板与自动匹配由全局 matchmaking 段控制 (关闭时两者都提示已关闭), 招募贴按 matchmaking.recruit-ttl-seconds 过期; 匹配成功后由队长用 /edungeon enter <副本ID> 发起挑战

队伍子命令 ​

用 /edungeon party <子命令> 管理队伍:

子命令说明限制
create创建一支新队伍 (自己当队长)已在队伍中时不可再建
invite <玩家>自己有队伍: 邀请对方入队 (仅队长); 自己没队伍: 向对方发起加入, 按邀请模式处理有队伍时仅队长可执行
accept邀请的接收方用来接受邀请; 申请的接收方 (队长) 用来批准申请按收到的是邀请还是申请而定
deny拒绝收到的邀请 (被邀请者) 或拒绝入队申请 (队长)按收到的是邀请还是申请而定
kick <玩家>踢出队员仅队长
leave自己离队 (队长离队时移交给其他队员)—
disband解散整支队伍仅队长
chat切换队伍频道: 开启后你的消息只有队伍可见—

邀请模式由全局配置 party.invite-mode 决定, 它控制没队伍的玩家向别人发起加入时的结果: public 直接加入, apply 提交申请等队长批准, invite 只有被邀请的人才能加入 (其他值按 invite 处理); 队伍人数上限见 party.max-size

随机地牢命令 ​

type: random 的副本走随机生成玩法, 用 /edungeon random <子命令> 操作:

子命令说明所需权限
create <副本ID> [人数] [种子]按随机生成配置为该副本创建一个随机地牢实例; 人数影响房量, 种子留空随机; 仅 type: random 的副本可用, 其他类型直接拒绝emakidungeon.play
enter <实例ID>进入已创建的随机地牢实例emakidungeon.play
leave离开当前随机地牢实例emakidungeon.play
list列出运行中的随机地牢实例 (实例 ID, 状态, 房间数, 种子)emakidungeon.play
records列出实例记录 (记录 ID 可用于 replay)emakidungeon.play
stop <实例ID>强制停止指定随机地牢实例emakidungeon.admin
replay <记录ID>按实例记录重新推演布局做回放校验emakidungeon.admin
reload重载 random-dungeon.yml 与全部副本的结构模板emakidungeon.admin

随机地牢的结构模板 (房间 / 走廊) 由编辑器的区域采集功能产出, 落库在 plugins/EmakiDungeon/world/<副本ID>/structures/; 采集流程见下面的编辑器会话命令, 生成参数见 配置详解

编辑器会话命令 ​

拥有 emakidungeon.editor 权限的玩家执行 /edungeon editor <副本ID> 后进入该副本的独立编辑世界与编辑会话, 可用子命令 (/edungeon editor <子命令>):

子命令说明
menu打开编辑主面板; type: random 的副本改为打开随机区域采集 GUI
pos1 / pos2记录区域的第一个 / 第二个角点 (站到目标区域的两个对角各记一次); type: random 的副本里用于框选要采集的结构区域
anchor add <锚点ID> <朝向> <宽> <高>在准星落点 (12 格内) 登记一个门点位: 朝向取 n / e / s / w, 宽高为门洞尺寸 (1–16); 需先框选区域, 仅 type: random 副本可用
anchor remove <锚点ID>移除指定门点位; 仅 type: random 副本可用
status查看当前区域采集会话 (结构类型, 标签, 门点位数, 点位数, 楼层); 仅 type: random 副本可用
mark <类型> [id]在视线 16 格内的方块上放一个标记, 暂存到会话, 保存后写入 flow.yml
marks列出本会话已暂存的标记
save把暂存的标记与面板改动回写模板文件并保存地形 (等同面板里的"保存并回写模板")
fill <方块>用 pos1 + pos2 圈出的区域批量填方块 (分帧写入, 有数量上限)
test测试开局: 走正常进入流程, 不计次数, 不上榜; 有未保存改动时会被拒绝
exit退出会话; 有未保存改动时会先拒绝, 要求保存或放弃

anchor 与 status 在非随机类型的副本里会提示仅随机类型可用; menu / pos1 / pos2 会按副本类型自动分流语义

标记按坐标记法分三种, 共 21 种模块类型 (与 flow.yml 的功能模块一一对应):

类型记法用途
entry单点入口落点 (全副本唯一, 重复放置会被拒绝)
room区域房间
checkpoint区域检查点
respawn单点重生点
exit单点出口
gate区域门禁封门区
spawn单点刷怪点
trigger区域触发区
block单点方块交互
chest单点奖励点
option单点选项节点
tip单点提示点
teleport区域传送区
boundary区域边界区
effect区域效果区
mechanism区域机关
room_timer区域房间计时
kill_target无坐标击杀目标
item单点物品交互
fx单点特效点
temp_item无坐标临时物品

记法说明: 单点标记对准方块直接记; 区域标记需要 pos1 + pos2 两个角点 (未记角点时首次 mark 会先把视线落点记为 pos1); 无坐标标记不落坐标, 只登记配置项. 每种类型可配的字段见 流程与触发器. Boss 不是独立标记: 刷怪点波次里的生物条目用 boss: true 标记

普通副本的编辑主面板 (元数据, 刷怪点与波次, 门禁, 分支选项) 通过 GUI 操作; 标记和面板改动都只是暂存, 点击"保存并回写模板" (或执行 save) 后才写进模板文件; 未保存就退出会丢弃全部改动

type: random 的副本里, 空手右键打开区域采集 GUI (元数据与标签, 门点位, 功能模块点位, 选区, 创建区域等面板): 主面板的"创建区域"可选房间 / 走廊, 按当前 pos1 / pos2 选区落库到 world/<副本ID>/structures/, ID 自动编号为 room_N / corridor_N; 落库后会话自动复位为新区域, 再次用 pos1 / pos2 框选就是下一个结构

同一副本模板同时只允许一个编辑会话

管理命令 ​

用 /edungeon admin <子命令> 执行管理操作, 需要 emakidungeon.admin 权限 (默认 OP):

子命令说明
instances列出全部运行中的实例 (实例 ID, 副本, 状态, 队伍, 写队列积压)
inspect <实例ID>查看实例详情: 难度, 掉落, 类型, 测试, 队伍, 已运行时长与流程时间线
stop <实例ID>强制结束指定实例
status运行状态总览: 实例数, 存活虚拟线程, 副本模板数, 各池占用与写队列
reload重载主配置与全部副本配置; 运行中的实例不受影响, 只对之后新建的实例生效
validate校验全部副本模板, 报告缺失 flow.yml 或配置非法的副本
poolreset <副本ID>强制重置该副本的池补位世界
clearslots清理残留的池占位记录

NOTE

admin 子命令在玩家判定之前分发, reload 也没有"只能由玩家执行"的限制: 控制台直接执行 /edungeon admin reload 即可重载, 脚本与假人同理; 玩家执行要求 emakidungeon.admin 权限, 控制台默认拥有全部权限

权限节点 ​

节点默认用途
emakidungeon.play所有玩家进入, 组队, 查询, 全局收听等玩家侧命令
emakidungeon.dungeon.*所有玩家全部副本的进入许可 (实际按每个 emakidungeon.dungeon.<副本ID> 逐个校验)
emakidungeon.bypass.limitOP绕过次数与冷却限制
emakidungeon.bypass.escapeOP逃逸防护豁免 (调试与维护用)
emakidungeon.scriptOP副本脚本装载与触发器注册
emakidungeon.editorOP地图编辑器会话
emakidungeon.adminOP实例管理, 强制结束, 重载, 池维护
emakidungeon.*OP以上全部的通配节点

emakidungeon.dungeon.<副本ID> 在插件启动与重载时按 world/ 下的副本目录动态注册, 默认所有玩家都能进; 副本被删除时对应节点一并移除. 想做"会员专属副本", 你在权限插件里把该节点的默认值关掉, 只授予指定组即可

副本内的命令限制 ​

进入副本后, 玩家发出的命令会依次过两道闸:

  1. 逃逸黑名单 (escape.blacklist, 支持通配符): 命中直接拒绝, 提示"该命令在本副本受限 (逃逸黑名单)", 这一层不可被任何放行条目豁免
  2. 命令管控 (commands.mode 为黑名单或白名单模式): 按全局 commands.rules 与副本级 commands.allow 判定, 拒绝时提示"该命令在本副本受限 (命令管控)"
