动画系统 ​

EmakiCoreLib 动画系统提供跨模块的动画时序基础设施：动画定义注册、按 tick 精确触发的关键帧（K帧）调度、优先级抢占与冲突裁决、播放生命周期监听。它只负责"什么时候发生什么"，不感知任何模型渲染——模型动画的实际播放由消费方（如 EmakiMobs）通过自己的模型后端桥接层完成。

核心概念 ​

概念类型说明
动画定义AnimationDefinition不可变 record：id、引擎动画名（engineAnimation，CoreLib 不解释）、时长（tick）、是否循环、优先级、冲突策略、关键帧列表。
关键帧AnimationKeyframe播放开始后第 tick 个 tick 触发；载荷是一行 CoreLib 动作管道（可为空，空帧仅作监听通知）。
优先级AnimationPriorityAMBIENT < UTILITY < ACTION < REACTIVE < TERMINAL 五档；高档抢占低档。
冲突策略AnimationConflictPolicy同优先级时 REPLACE（替换）或 REJECT（拒绝新请求）。
播放句柄AnimationPlaybackHandlePLAYING / FINISHED / CANCELLED 三态，cancel() 幂等。
播放监听AnimationListeneronPlay / onKeyframe / onStop，回调运行在实体 owner 线程。

第三方插件 API ​

依赖 emaki-corelib-api（provided，禁止 shade）。所有入口在 EmakiCoreLibApi：

java
// 注册动画定义（owner-scoped，可撤销；注册表在 CoreLib reload 后存活，无需重建回调）
AnimationRegistration reg = EmakiCoreLibApi.registerAnimation(plugin,
    AnimationDefinition.of("my_boss_slam", "slam_anim", 30, false,
        AnimationPriority.ACTION, AnimationConflictPolicy.REPLACE,
        List.of(
            AnimationKeyframe.of(0, "self | play_sound sound=minecraft:entity.wither.shoot", "windup"),
            AnimationKeyframe.of(12, "self | spawn_particle particle=explosion", "impact")
        )));

// 播放（任意线程可调；future 完成线程不固定）
CompletableFuture<EmakiResult<AnimationPlaybackHandle>> future =
    EmakiCoreLibApi.playAnimationAsync(plugin, entity, "my_boss_slam",
        CoreActionExecutionContext.builder().caster(entity).phase("animation").build());

// 停止 / 监听
EmakiCoreLibApi.stopAnimation(plugin, entity, "my_boss_slam");
AnimationRegistration listener = EmakiCoreLibApi.addAnimationListener(plugin, new AnimationListener() {
    @Override public void onPlay(Entity e, AnimationDefinition d, UUID id) {
        // 在这里把 d.engineAnimation() 转发给你的模型后端
    }
});

线程与生命周期契约 ​

  • playAnimationAsync 可从任意线程调用；K帧动作行在实体 owner 线程执行（Folia 安全），调度走 CoreLib ExecutionDispatcher。
  • 关键帧载荷经共享动作引擎编译并按行缓存；编译失败的行打印告警并跳过，不影响其余帧。
  • 句柄必须在 onDisable 关闭；owner 插件被禁用时注册与在飞播放自动撤销。
  • 动画定义注册表在 CoreLib reload 后存活，无需重建回调；需要重放注册的是动作段表（registerActionStage 等），它会在 reload 时重建，必须用 onStageRegistryRebuilt / addStageRegistryRebuildListener 重放。
  • 未安装 CoreLib 时所有入口返回稳定的 unavailable/inactive 对象，不抛异常。

与 EmakiMobs 的分工 ​

层归属内容
时序基础设施EmakiCoreLib定义注册表、K帧调度、优先级裁决、监听分发
模型渲染桥EmakiMobsModelEngine / BetterModel 桥接、engineAnimation 解释、LOD
玩法映射EmakiMobsidle/walk/run/attack/hurt/death 等标准动作与触发器绑定

怪物语义（哪个生物配哪个蓝图、受伤播哪个动画）不进入 CoreLib；CoreLib 也不引用任何模型插件类。

配置 ​

动画系统本身无配置节；K帧时长、优先级、冲突策略全部来自注册方。消费方的模型/LOD 配置见 EmakiMobs 实体模型与动画。
