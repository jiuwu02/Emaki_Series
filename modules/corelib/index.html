EmakiCoreLib ​

EmakiCoreLib 是 Emaki 系列所有业务插件的共享运行时核心。它本身不提供完整玩法循环，而是提供跨插件复用的底层能力：动作系统、GUI 模板、物品来源、PDC、物品装配、条件、表达式、经济、权重、调度兼容和 bStats 托管。

NOTE

分区原则：这里记录"所有插件都能复用"的能力。Attribute、Forge、Strengthen、Cooking、Gem、Skills、Item、Level 等插件自己注册的动作、API、配置字段和玩法流程，放在对应插件文档中说明。

安装边界 ​

服务器只安装插件本体 Jar：

text
plugins/
├── EmakiCoreLib-4.8.1.jar
└── EmakiAttribute-4.8.0.jar / EmakiForge-4.8.0.jar / ...

不要把 emaki-corelib-api-*.jar 放进服务器 plugins/。API Jar 只给第三方开发者作为 Maven provided 或 Gradle compileOnly 编译依赖使用。

CoreLib 提供什么 ​

通用动作系统 ​

动作系统允许各插件在 YAML 中执行消息、音效、粒子、命令、经济、经验、临时物品、方块、传送和动作模板。动作语法、控制前缀、CoreLib 内置动作，以及 /corelib action list|run 管理命令见 动作系统。

业务插件可以向同一个注册表追加自己的动作。例如 Level 的等级经验动作、Attribute 的属性动作、Skills 的技能动作都应在对应插件页面中查参数，不再集中塞在 CoreLib 页面里。

GUI 系统 ​

GUI 系统提供菜单模板、槽位解析、按钮、点击处理、会话管理、物品来源解析和动态渲染基础。业务插件只声明自己的 GUI 文件与流程逻辑。详情见 GUI 系统。

物品来源 ​

物品来源系统统一解析 Vanilla、CraftEngine、ItemsAdder、Nexo、Oraxen、EcoItems、MMOItems、NeigeItems、EmakiItem 等来源，让配方、材料、奖励和 GUI 槽位不依赖显示名或 Lore。详情见 物品来源系统。

物品匹配器 ​

在物品来源之上，匹配器（matcher）追加组件、PDC、Lore、表达式等条件，用于判定"玩家放进来的物品算不算材料"。全系 9 个模块的输入匹配点共用同一套语法，详情见 物品匹配器。

PDC 与物品装配 ​

CoreLib 统一封装 Bukkit PersistentDataContainer，并通过 Assembly 把不同模块写入的 layer 合成为最终名称和 Lore。Forge、Strengthen、Gem、Item、Attribute 等模块都通过这条链路避免互相覆盖展示。详情见 PDC 服务、物品装配系统 和 名称与 Lore 操作。

共享玩法事件 ​

CoreLib 会把部分 Bukkit / MythicMobs 玩法事件统一归一成配置用的事件 ID，供 EmakiLevel 的经验来源和 EmakiCodex 的成就触发器复用。可填写的 ID 与变量见 共享玩法事件 ID。

条件、表达式、经济和权重 ​

  • 条件系统：通用条件表达与条件组。
  • 表达式引擎：费用、概率、等级、伤害和配置公式。
  • 经济桥接：Vault / ExcellentEconomy provider 与动态枚举。
  • 权重系统：随机池、品质池、奖励池和保底池的通用工具。

推荐阅读顺序 ​

服主 / 配置维护者 ​

  1. 物品来源系统：先学会如何稳定引用材料和奖励。
  2. 物品匹配器：在此之上按组件、PDC 等条件收窄输入判定。
  3. 动作系统：掌握成功、失败、奖励和提示写法。
  4. 条件系统：配置权限、物品、状态和表达式判断。
  5. 表达式引擎：编写费用、概率和数值公式。
  6. GUI 系统：调整菜单布局和按钮交互。
  7. 对应业务插件页面：配置真正的玩法流程。

第三方开发者 ​

  1. PDC 服务：了解共享数据写入边界。
  2. 物品装配系统：了解多模块展示合并规则。
  3. 对应插件 [API 与集成] 页面：调用业务 API，不依赖实现类。

默认配置目录 ​

text
plugins/EmakiCoreLib/
├── config.yml
└── lang/
    ├── zh_CN.yml
    └── en_US.yml

config.yml 管理语言、GUI 后端、共享玩法事件、动作循环与动作模板，以及全局 Debug；将 debug.global_all 设为 true 会为所有使用 CoreLib DebugLogger 的 Emaki 模块输出 Debug 日志。管理员也可用 /corelib debug all on|off|status 临时切换，CoreLib 重载后会重新采用配置值。lang/ 管理 CoreLib 自身消息。业务插件会生成自己的配置目录，不建议把业务配置混放进 CoreLib。
