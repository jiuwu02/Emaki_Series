命令与权限 ​

EmakiCooking 的命令与权限节点列在下面, 工位 (世界里用来做菜的那块方块) 出问题时先用哪条命令一并注明

EmakiCooking 的主命令是 /ecooking, 别名为 /ec. 管理员用它重载工位配置, 检查手里物品或目标方块是什么来源, 重建工位索引, 查看运行调试信息

命令列表 ​

命令权限说明
/ec helpemakicooking.use显示帮助
/ec reloademakicooking.reload 或 emakicooking.admin重载主配置, 语言文件, 工位, 配方, 界面和物品调整
/ec inspect handemakicooking.inspect, emakicooking.use 或 emakicooking.admin检查手里物品是什么来源, 能不能用于烹饪匹配
/ec inspect blockemakicooking.inspect, emakicooking.use 或 emakicooking.admin检查准星 6 格内目标方块的工位类型, 方块状态, TileState, PDC/YAML 后端和索引状态
/ec station reindexemakicooking.admin重建工位坐标索引, 扫描旧版 YAML 和当前已加载区块里的 PDC 工位
/ec convert-legacy [confirm]emakicooking.admin把配置里旧的扁平 matcher 键迁移成同级的 item_sources + matcher, 或迁移成嵌套的角色节点; 发酵桶的 inputs[] 保留旧键, 以兼容已经持久化的槽位身份. 不带参数只预演, 加 confirm (或 --apply) 才会写到文件并保留备份
/ec debug [status|on|off|player <玩家>|module <模块>]emakicooking.debug 或 emakicooking.admin输出运行时的调试信息, 见下方子命令说明

不带参数执行 /ec 与 /ec help 等价, 都会打印帮助. 无法识别的子命令会提示 general.unknown_command

营养命令 ​

/ec nutrition 用于查询和管理玩家营养值. 营养玩法说明见 营养系统

命令权限说明
/ec nutrition get [玩家] [类型]emakicooking.nutrition.use, emakicooking.nutrition.admin 或 emakicooking.admin查询营养值. 不带类型就列出全部类型的 值 / 上限; 带类型返回该类型的当前值. 玩家可省略 (默认查自己, 控制台必须指定)
/ec nutrition set <玩家> <类型> <数值>emakicooking.nutrition.admin 或 emakicooking.admin设置指定玩家某营养类型的值
/ec nutrition add <玩家> <类型> <数值>emakicooking.nutrition.admin 或 emakicooking.admin增加指定玩家某营养类型的值
/ec nutrition remove <玩家> <类型> <数值>emakicooking.nutrition.admin 或 emakicooking.admin减少指定玩家某营养类型的值
  • set, add, remove 需要四段参数齐全, 目标玩家必须在线, 数值写入后按类型的 min~max 截断
  • 营养系统未启用时, 营养命令会提示已禁用

先用哪个命令 ​

场景先执行目的
改了工位, 配方, GUI 或语言/ec reload重载 Cooking 的运行配置
材料, 燃料或容器不匹配/ec inspect hand查看手里物品被识别成什么来源
工位方块, PDC 后端或索引异常/ec inspect block查看目标方块是否为 TileState, 当前后端, PDC/YAML 状态和索引记录
迁移旧 YAML, 换方块或重启后工位缺失/ec station reindex重建 data/stations/index/<world>.idx 坐标索引
工位监听或展示异常/ec debug查看运行时状态和调试输出

常见操作 ​

检查手持物来源 ​

text
/ec inspect hand

你用它确认手里物品能不能被识别成配方输入, 容器, 燃料, 工具或工位方块, 排查自定义物品来源时先用它

检查目标工位方块 ​

text
/ec inspect block

用来查看准星 6 格内目标方块的工位类型, 物品来源, block_state, tile_state, storage_backend, pdc_state, indexed, index_backend 和 legacy_yaml. 工位很多的服务器可以用它确认工位方块是不是走 BLOCK_PDC, 走 BLOCK_PDC 能少生成独立的 YAML 文件

重建工位坐标索引 ​

text
/ec station reindex

你用它扫描旧 YAML 状态和当前已加载区块里的 PDC 工位, 重建 data/stations/index/<world>.idx. 迁移旧数据, 替换方块实体, 或发现 ChunkLoad 后工位没恢复时先用它

重载烹饪配置 ​

text
/ec reload

重载后先看一眼控制台输出. 如果新增了工位方块, 界面或配方目录, 先在测试服验证状态保存和交互流程

调试运行状态 ​

text
/ec debug
/ec debug status
/ec debug on
/ec debug off
/ec debug player <玩家>
/ec debug module <模块>
子命令说明
不带参数 / status输出当前调试开关, 被跟踪玩家和已开启模块
on / off全局开启或关闭调试输出
player <玩家>切换只跟踪该在线玩家; 省略玩家名时列出可用模块
module <模块>切换单个模块的调试输出. EmakiCooking 可用模块: recipe, stir, display, station, pdc (另含 CoreLib 共享模块)

无法识别的子命令会回退为输出状态. 适合排查工位监听, 展示实体, 配方匹配, 持久化状态等问题. 正式服长期排查时, 配合控制台日志使用, 避免玩家端信息过多

排查建议 ​

  • 工位无法使用: 检查方块来源, 工位权限和交互方式是否匹配
  • 工位状态或后端不确定: 对准目标方块执行 /ec inspect block, 确认 tile_state, storage_backend, pdc_state, indexed 和 legacy_yaml
  • 重启或区块加载后工位未恢复: 先执行 /ec station reindex 重建索引, 再观察控制台是否出现 lost_block_entity_replaced 或 mismatch 报告
  • 材料无法放入: 检查 input_rules.only_recipe_items, 配方目录和物品来源
  • 榨汁机无法盛取: 检查流体容量是否达到容器 serving_ml, 并确认玩家拥有 emakicooking.station.juicer.collect
  • 发酵桶无法开始: 检查输入是否匹配配方, 玩家是否拥有 start 权限
  • 烤炉不推进: 检查火力是否处于配方要求区间, 燃料是否生效
