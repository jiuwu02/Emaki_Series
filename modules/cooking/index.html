EmakiCooking ​

下面依次说明 EmakiCooking 做什么, 有哪些工位, 配置放在哪里, 以及全局配置项怎么填

EmakiCooking 负责在世界里用方块工位做菜. 工位就是世界里用来做菜的那块方块. 它提供砧板, 炒锅, 研磨机, 蒸锅, 烤炉, 榨汁机和发酵桶七类工位. 它管的是方块交互, 坐标状态, 材料输入, 阶段进度和分支产物, 与装备成长无关

七类工位 ​

工位典型玩法
砧板 chopping_board把食材切成另一种形态
炒锅 wok加入材料后控制火候, 翻炒, 出锅
研磨机 grinder把物品磨成粉末或其他材料
蒸锅 steamer打开界面加燃料和水分, 按蒸制进度出成品
烤炉 oven加燃料提升火力, 火力合适时才推进烘烤, 结果由烘烤阶段决定
榨汁机 juicer反复压榨材料生成流体, 再用容器按容量盛取饮品
发酵桶 fermentation_barrel投入多种材料后开始发酵, 可以提前收取, 正常完成和过度发酵各有不同结果

目录说明:

目录 / 文件作用
recipes/各工位的配方. 改配方先从对应工位的目录开始
gui/steamer.yml蒸锅的界面配置
gui/oven.yml烤炉的界面配置
gui/juicer.yml榨汁机的界面配置
gui/fermentation_barrel.yml发酵桶的界面配置
item_adjustments/对输入或输出物品的额外调整
nutrition/营养类型定义, 随包提供 grain.yml, protein.yml, vegetable.yml, fruit.yml, sugar.yml. 详见营养系统文档
data/nutrition/玩家营养值持久化数据, 每个玩家一个 <UUID>.yml
data/stations/普通方块工位的 YAML 回退状态目录. 方块实体工位优先把状态写进方块 PDC
data/stations/index/每个世界一个 <world>.idx, 记录工位坐标, 类型, 物品来源和存储后端, 供区块加载时恢复工位
data/stations-legacy-backup/旧 YAML 状态成功迁移到方块实体 PDC 后, 原文件备份到这里
data/station-tombstones/工位被移除时写入墓碑标记的目录, 用来阻止已删除的工位被重新索引, 或在状态残留时复活
config.yml工位识别, 交互, 限制, 展示实体, 燃料和流体容量等全局配置

全局配置项 ​

以下是 config.yml 的顶层字段; 工位段与营养段分别在 工位系统 与 营养系统 中给出

字段类型必填默认值取值范围说明
versionstring否"5.0.0"—配置版本号, 升级迁移时用来比对
languagestring否"zh_CN"lang/ 下存在的语言文件名语言文件, 对应 lang/<language>.yml
release_default_databoolean否truetrue / false是否释放内置的示例数据 (recipes/, item_adjustments/, nutrition/). config.yml 与 lang/ 属于版本化文件, gui/ 属于静态文件, 不受这一项控制
input_rules.only_recipe_itemsboolean否truetrue / false全局严格模式. 工位段没单独写 only_recipe_items 时用这里的值
station.disabled_worldslist<string>否[] (不禁用任何世界)世界名, 大小写不敏感全局禁用工位交互的世界列表. 命中后插件不接管方块交互, 保留原版行为. 随包提供的 config.yml 里只留了注释, 没有写出这个键
yaml
# 只允许可匹配当前工位配方的物品进入输入
input_rules:
  only_recipe_items: true

# 资源世界与副本世界保留原版交互
station:
  disabled_worlds:
    - world_resource

世界状态流程 ​

  1. 玩家和工位方块交互
  2. Cooking 判断这个方块是不是配置里的工位
  3. 读取这个坐标上的工位状态
  4. 根据玩家手里的物品, 权限, 容器, 燃料和配方执行操作
  5. 更新工位状态, 例如加入材料, 切割次数, 火候, 燃烧时间, 蒸汽, 水分, 流体容量或发酵进度
  6. 条件满足后发放产物, 盛取流体, 进入下一阶段或执行动作
  7. 如果工位方块是方块实体, 状态写进方块 PDC 并记录索引; 普通方块则回退写入 data/stations/ 的 YAML
  8. 重启或区块加载时, Cooking 根据 data/stations/index/<world>.idx 定位并恢复工位状态

与外部方块插件的关系 ​

有 CraftEngine, ItemsAdder, Nexo 这些软依赖时, Cooking 能识别它们提供的自定义方块或物品. 没装这些插件时, 对应的自定义工位不会生效, 但原版物品和方块相关功能仍可按配置运行

展示实体可通过 display_entities.backend 配置:

  • auto: 装了 PacketEvents 就用虚拟展示实体, 不可用时回退到 Bukkit 的真实 ItemDisplay
  • packet_events: 优先使用 PacketEvents, 加载失败仍然回退到 Bukkit
  • bukkit: 始终使用 Bukkit 的真实 ItemDisplay
