定义编辑器 ​

这页讲 EmakiSkills 的游戏内定义编辑器: 怎么打开, 浏览器和编辑页两个界面怎么用, 能编辑哪些定义, 修改怎么校验和保存, 以及 edit-backups 备份机制

编辑器面向服主和配置者: 不出游戏, 不碰文本编辑器, 就能浏览, 新建, 修改和删除 skills/ 与 resources/ 下的定义文件. 技能字段和资源字段本身怎么配, 还是看 技能定义; 这页只讲编辑器本身

打开编辑器 ​

命令效果
/eskills edit打开定义浏览器, 列出全部分类和定义文件
/eskills edit <id>直接打开该定义的编辑页; id 支持 Tab 补全 (补全范围是技能定义与本地资源的全部 id)

权限是 emakiskills.edit 或 emakiskills.admin (默认 op), 且只接受玩家执行: 控制台执行会提示仅限玩家. id 认不出来时回复"无法打开 %id% 的编辑界面"

能编辑哪些定义 ​

浏览器按分类浏览, 每个分类对应一个目录:

分类位置新建骨架
技能定义skills/*.ymlid, display_name, description, icon_material, trigger_type, cooldown_ticks, global_cooldown_ticks, tags, tab_tags, conflicting_skills, required_skills, show_in_slots, ui_category, sort_order, enabled, resource_costs, variables, script, upgrade
本地资源resources/*.ymlid, display_name, max, default_current, regen_amount, regen_interval_ticks, clamp_min, clamp_max
  • 文件的 ID 取文件内容里的 id, 读不到时退回文件名 (去掉扩展名).
  • 新建定义时会按骨架预填字段; 技能骨架里 script 预填 mode: native 的空动作管道, upgrade 预填 max_level: 1 的关闭状态, 你再逐项改.
  • 发货的示例技能 (example_*.yml) 和示例脚本技能也是普通定义文件, 同样可以浏览和编辑, 不想要就删掉

定义浏览器 (editor_browser_gui.yml) ​

/eskills edit 无参打开的就是定义浏览器: 跨分类列出定义文件, 每页一屏. 界面模板是 gui/editor_browser_gui.yml, 5 行布局 (第 1 行返回/关闭, 2-4 行内容, 5 行翻页与新建):

槽位键类型默认位置含义
doc_entryfield_entry2-4 行内容区定义条目; 左键打开进入编辑页, 右键删除 (二次确认, 删前自动备份)
backback0返回/关闭浏览界面
closeclose8关闭浏览界面
page_prevpage_prev36上一页
page_infopage_info38当前页码与定义数 (%current_page%, %total_pages%, %menu_title%, %entry_count%)
page_nextpage_next40下一页
new_docnew_doc42新建定义: 先选分类, 再在聊天栏输入新定义的 ID
borderfiller其余格子边框填充, 不可交互

新建规则: ID 只允许小写字母, 数字和下划线 (例如 my_skill); 非法 ID, 与已有定义重名, 或该分类不支持新建时都会拒绝并给出提示 (技能与本地资源两个分类都支持新建和删除). 删除要按两次: 第一次点"删除"出确认界面, 再点"确认删除"才执行, 中途点"取消"什么都不动

编辑页 (editor_page_gui.yml) ​

点开某个定义 (或 /eskills edit <id>) 进入编辑页. 所有子菜单共用 gui/editor_page_gui.yml, 标题随当前子菜单替换, 字段渲染进内容区网格:

槽位键类型默认位置含义
previewpreview4定义预览: 按草稿里的 icon_material / display_name 生成一个展示物品
field_entryfield_entry2-4 行内容区字段条目, 操作方式见下表
back_parentback_parent0返回上一级菜单
back_homeback_home1返回编辑器主页
closeclose8关闭编辑界面
confirmconfirm36"添加": 向当前列表新增一项
page_prevpage_prev38上一页
page_infopage_info40当前页码与条目数
page_nextpage_next42下一页
borderfiller其余格子边框填充, 不可交互

技能定义的深层字段各有子菜单: 释放条件, 技能变量, 技能脚本 (含 cast/hit/miss/fail 动作阶段), 升级配置 (含升级经济), 资源消耗条目. 字段操作 (提示文案就是这么写的):

字段形态操作
开关左键切换 开/关, 右键重置
枚举左键切换到下一个取值, 右键重置
数值左键在聊天栏输入数值, 右键重置
文本左键在聊天栏输入文本, 右键重置
子菜单左键进入
列表左键查看; 序列列表: 左键加一行, Shift+左键改条目, 右键删最后一行, Shift+右键清空
映射左键改条目 (聊天栏按"键=值"输入), 右键重置整个节点

聊天栏输入时输入 cancel 取消; 映射条目格式不对会提示按"键=值"输入

校验与保存 ​

  • 每次修改字段都立即校验: YAML 必须可解析, 定义 ID 不能为空也不能改 (改了报 id_changed), 定义内容要能被对应解析器读取 (技能走技能解析器, 本地资源走资源解析器). enabled: false 的技能跳过解析校验, 可以先关掉再慢慢改.
  • 校验通过: 聊天栏提示"成功修改了 %item%", 并播一个经验球音效; 校验失败: 提示原因并播村民拒绝音效, 修改不生效. 解析失败 (definition_parse_failed) 的详细原因在控制台.
  • 修改会记入编辑会话, 由插件在落盘时机统一写入文件: 执行 /eskills reload 之前, 以及插件关闭之前, 都会先把没写盘的修改落盘. 改完想立即生效, 就跑一次 /eskills reload.
  • 新建和删除会立刻重载模块, 定义马上生效.
  • 文件被外部程序同时改动时, 写盘会按版本检查拒绝覆盖 (提示冲突), 不会悄悄盖掉别人的修改; 单个定义文本过大也会被拒绝保存

edit-backups 备份 ​

每次写盘前, 被覆盖的旧文件内容会先备份到:

text
plugins/EmakiSkills/edit-backups/<毫秒时间戳>/<文件名>.yml

删除定义时也一样: 文件先复制进 edit-backups, 再从定义目录里删掉, 所以确认界面上写的是"此操作不可撤销; 删除前会自动写入 edit-backups 备份"——真删错了, 去备份目录把文件拷回来就行. 备份按时间戳分目录, 不会互相覆盖, 记得定期清理
