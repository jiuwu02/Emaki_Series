触发器 ​

Skills 触发器决定技能什么时候被释放。系统分为主动触发器和被动触发器两种架构。

架构概述 ​

  • 主动触发器：玩家在 GUI 中将技能绑定到触发器槽位，进入施法模式后通过对应操作释放。
  • 被动触发器：技能配置中通过 passive_triggers 声明，满足条件时自动触发。
text
主动技能：玩家在 GUI 绑定技能到 right_click 槽位 → 进入施法模式后右键释放
被动技能：技能配置 passive_triggers: [attack] → 攻击命中时自动触发

注册表由两部分组成：插件内置的默认触发器定义，加上 config.yml 中 triggers / passive_triggers 的同名覆盖。因此 config 只负责显示名、启用状态与互斥声明；要新增一个内置清单以外的触发器 id（例如 consume），必须在 config 中显式注册，否则派发时会被丢弃且不报错。

主动触发器 ​

主动触发器是全局槽位，玩家通过技能 GUI 将技能绑定到某个槽位，进入施法模式后执行对应操作即可释放。

触发器操作
left_click左键
right_click右键
shift_left_clickShift + 左键
shift_right_clickShift + 右键
drop_qQ 键丢弃
hotbar_1 ~ hotbar_9数字键 1~9

NOTE

主动触发器的冷却由技能定义中的 cooldown_ticks 和 global_cooldown_ticks 控制，不在触发器层面配置。

triggers 配置 ​

yaml
triggers:
  left_click:
    display_name: "[左键]"
    enabled: true
    incompatible_with:
      - shift_left_click
字段类型必填默认值取值范围说明
triggers.<id>map否内置默认定义—触发器 id 即键名。写成标量值时该键被跳过。
triggers.<id>.display_namestring否键名；空白回退 UnknownMiniMessageGUI 与 ActionBar 中显示的触发器名。
triggers.<id>.enabledboolean否truetrue / false关闭后该触发器不再派发，也不能在 GUI 中绑定。
triggers.<id>.incompatible_withlist<\string>否[]触发器 id 列表声明互斥触发器；互斥是双向的（见下文冲突解决）。

主动触发器全局设置 ​

yaml
trigger_settings:
  # 启用后仍分发已被 Bukkit 取消的事件；关闭可避免保护插件拦截后继续耗能或施法。
  legacy_dispatch_cancelled_events: false
字段类型必填默认值取值范围说明
trigger_settings.legacy_dispatch_cancelled_eventsboolean否falsetrue / false是否仍分发已被 Bukkit 取消的交互 / 丢弃 / 切换物品栏事件。默认 false：事件被取消时不再派发，避免保护类插件拦截后继续耗能或施法；改为 true 会恢复旧行为，并在启用时输出一次弃用警告。

被动触发器 ​

被动技能通过 trigger_type: passive 和 passive_triggers 列表声明。当列表中的事件发生时，自动尝试释放。

yaml
id: lifesteal_passive
trigger_type: passive
passive_triggers:
  - attack
cooldown_ticks: 60

consume 需要自行在 config.yml 注册

监听器会为 PlayerItemConsumeEvent（吃下食物或饮料）派发 consume，但 consume 既不在内置默认触发器里，也不在随插件发货的 config.yml > passive_triggers 中。未注册的触发器在派发时被直接丢弃，因此只写 passive_triggers: [consume] 不会有任何效果，也不会报错。

要启用它，需先在 config.yml > passive_triggers 下补一节：

yaml
passive_triggers:
  consume:
    display_name: "[进食]"
    enabled: true
    incompatible_with: []

passive_triggers 配置 ​

yaml
passive_triggers:
  attack:
    display_name: "[攻击命中]"
    enabled: true
字段类型必填默认值取值范围说明
passive_triggers.<id>map否内置默认定义—被动触发器 id 即键名。写成标量值时该键被跳过。
passive_triggers.<id>.display_namestring否键名；空白回退 UnknownMiniMessage显示名。被动触发器不能由玩家在 GUI 中绑定，该值主要供展示使用。
passive_triggers.<id>.enabledboolean否truetrue / false关闭后该被动触发器不再派发。
passive_triggers.<id>.incompatible_withlist<\string>否[]触发器 id 列表与主动触发器同义；被动触发器无需玩家绑定，一般留空。

被动触发器全局设置 ​

yaml
passive_trigger_settings:
  # timer 的检查间隔，单位：tick；小于 1 的值会按 1 处理。
  timer_interval_ticks: 20
  # combo_attack 的超时，单位：tick；超时未攻击时重置连击计数。
  combo_timeout_ticks: 60
字段类型必填默认值取值范围说明
passive_trigger_settings.timer_interval_ticksinteger否20≥ 1，小于 1 按 1timer 被动触发器的检查间隔，单位 tick。
passive_trigger_settings.combo_timeout_ticksinteger否60≥ 1，小于 1 按 1combo_attack 连击状态的超时，单位 tick；超过该间隔未攻击会重置连击计数。

Cron 被动触发器 ​

技能定义中填写了 cron_expression 时，会自动注册一个 ID 为 cron_<技能 id> 的被动触发器，并加入该技能的 passive_triggers，无需手写。表达式格式与 spawn_rules 的 cron 一致，见 CoreLib 表达式 · Cron 表达式。cron_max_executions 限制总触发次数，0 表示不限。表达式非法时会记录警告并跳过该技能。

触发器冲突解决 ​

触发器之间存在互斥关系，通过 incompatible_with 声明双向互斥：

  • 每个触发器与自身冲突（同一触发器不能绑定两个技能）。
  • 互斥的触发器之间不能同时绑定技能（如 left_click 与 shift_left_click）。

冲突矩阵在配置加载时构建，玩家在 GUI 中绑定时会自动检查冲突。内置默认触发器声明了四组互斥：left_click ↔ shift_left_click、right_click ↔ shift_right_click。

施法模式 ​

主动技能需要进入施法模式才能释放。

yaml
cast_mode:
  # 入口固定为 F；enabled 仅控制 F 键切换，不是施法模式总开关。
  entry_key: "f"
  # false 时 F 恢复原版换手，命令和 GUI 仍可切换。
  enabled: true
  # 玩家重新加入后是否恢复上次的施法模式状态。
  restore_last_state_on_join: true
字段类型必填默认值取值范围说明
cast_mode.entry_keystring否"f"恒为 f入口键。源码在构造配置时固定赋值为 f，配置里写其他值不会生效。
cast_mode.enabledboolean否truetrue / false是否启用 F 键切换施法模式。false 时 F 键恢复原版换手，命令与 GUI 仍可切换。
cast_mode.restore_last_state_on_joinboolean否truetrue / false玩家重新加入后是否恢复上次的施法模式状态。
  • 默认按 F 键切换施法模式。
  • 施法模式开启后，主动触发器才会监听左键、右键、Q 键、数字键等服务端可见操作；未进入施法模式时这些操作不会派发技能。
  • 施法模式下 ActionBar 显示技能槽信息，模板与变量见 技能状态栏。

配置示例 ​

主动技能 ​

yaml
id: fireball
trigger_type: active
display_name: '<red>火球术'
cooldown_ticks: 100
global_cooldown_ticks: 20
resource_costs:
  - type: ea-resource
    target_id: mana
    amount: 20
    operation: consume

玩家在 GUI 中将火球术绑定到 right_click 槽位，进入施法模式后右键释放。

被动技能 ​

yaml
id: thorns_aura
trigger_type: passive
passive_triggers:
  - damaged_by_entity
display_name: '<yellow>荆棘反击'
cooldown_ticks: 40

被实体伤害时自动触发，受 cooldown_ticks 冷却限制。

定时被动 ​

yaml
id: regen_aura
trigger_type: passive
passive_triggers:
  - timer
display_name: '<green>恢复光环'
cooldown_ticks: 0
resource_costs:
  - type: ea-resource
    target_id: mana
    amount: 5
    operation: consume

按全局 timer_interval_ticks 间隔自动触发。

连击被动 ​

combo_attack 派发时会在触发调用里附带 combo_count（本次连击计数），技能可用它做条件或变量判断。随插件发货的 skills/example_combo_skill.yml 用条件块读取它：

yaml
id: combo_finisher
trigger_type: passive
passive_triggers:
  - combo_attack
condition:
  type: all_of
  entries:
    - "%combo_count% >= 5"
cooldown_ticks: 100

条件表达式里的 %...% 需要能被 PlaceholderAPI 解析，细节见 技能定义 · condition 条件块。combo_attack 以刚被攻击的实体作为目标与范围中心。
