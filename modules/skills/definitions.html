技能定义 ​

技能文件位于 plugins/EmakiSkills/skills/*.yml。EmakiSkills 负责定义技能的管理层信息，技能效果可通过原生脚本系统或 MythicMobs 执行。本地资源定义位于 plugins/EmakiSkills/resources/*.yml。

加载规则 ​

  • 一份文件只加载一个技能，文件内 id 为空时整份文件被跳过并计入加载问题。
  • enabled: false 的技能不进入注册表，等同于该技能不存在。
  • 技能 id 会被规范化为小写；列表类字段里的 id 统一做 id 规范化并把 - 折叠为 _。
  • 列表字段支持别名键（见下表），两处同时书写时按顺序合并去重。

顶层字段 ​

yaml
id: "fireball"
enabled: true
display_name: "<red>火球术"
description:
  - "<gray>向前方释放一枚火球。"
icon_material: "fire_charge"
mythic_skill: "EmakiFireball"
trigger_type: "active"
cooldown_ticks: 100
global_cooldown_ticks: 20
字段类型必填默认值取值范围说明
idstring是—非空；转小写技能唯一 ID。空值使整份文件被跳过。
enabledboolean否truetrue / false是否启用。false 时技能不加载，等同于不存在。
display_namestring否id任意 MiniMessage 文本显示名，用于 GUI、ActionBar 与反馈文案的 %skill%。
descriptionlist<\string>否[]—技能描述行，显示在 GUI 中。
icon_materialstring否""Bukkit Material 名（转小写）GUI 图标材质。留空时用槽位配置或内置兜底材质。
mythic_skillstring否""MythicMobs 技能 idmythic / hybrid 模式下执行的 MythicMobs 技能，也用于非玩家施法者路径。
trigger_typestring否"active"active / passive（其他值一律按 active）主动或被动技能。
passive_triggerslist<\string>否[]已注册的被动触发器 id被动技能的事件来源。未注册的 id 在派发时被丢弃，不报错。
cron_expressionstring否""Quartz cron 表达式非空时自动注册 cron_<id> 被动触发器并加入 passive_triggers；格式见 CoreLib 表达式 · Cron 表达式。
cron_max_executionsinteger否0≥ 0，负数按 0cron 触发器总触发次数上限；0 表示不限。
variablesmap否{}键名不以 emaki_ 开头运行时变量块，写法见 变量类型。
scriptmap否禁用—原生脚本块，写法见 原生脚本系统。
upgrademap否禁用—升级规则，见下文。
cooldown_ticksinteger否0≥ 0，负数按 0技能自身冷却，单位 tick（20 tick = 1 秒）。
global_cooldown_ticksinteger否0≥ 0，负数按 0全局冷却，单位 tick；释放后所有技能共享该冷却。
resource_costslist<\map>否[]—资源消耗或检查，条目字段见下文。
lore_aliaseslist<\string>否[]—从装备 Lore 识别技能时匹配的别名。
pdc_skill_idstring否id—从装备 PDC 识别技能时使用的 ID。
tagslist<\string>否[]命中 skill_tags.equip_limits 时受数量限制技能标签，用于装备数量限制与分类筛选。
tab_tagslist<\string>否[]别名 tabTagsGUI 页签标签。
required_skillslist<\string>否[]别名 dependencies装备此技能前必须已经装备的技能 ID。
conflicting_skillslist<\string>否[]别名 conflicts不能与此技能同时装备的技能 ID。
ui_categorystring否"default"—GUI 分类。
sort_orderinteger否0越小越靠前GUI 排序。
show_in_slotsboolean否truetrue / false是否允许出现在玩家主动技能槽选择列表中。装备强制触发器技能常设为 false。
conditionmap否无—技能释放（及升级）条件块，见下文。

condition 条件块 ​

技能释放与升级共用同一条件块。条件表达式在求值前会先经过 PlaceholderAPI 渲染。

yaml
condition:
  type: "all_of"
  entries:
    - "%player_level% >= 5"
    - "%emakiskills_level_fireball% >= 2"
字段类型必填默认值取值范围说明
conditionmap否无—条件块。必须写成映射节点；缺少 entries 时视为无条件。
condition.typestring否all_ofall_of、any_of、none_of、at_least、exactly多条件组合方式。
condition.entrieslist<\string>否[]表达式字符串条件表达式列表；不写该键则整块条件为空。
condition.required_countinteger否0≥ 0at_least / exactly 组合方式下的命中数量阈值。
condition.invalid_as_failureboolean否truetrue / false由通用条件解析器读取；EmakiSkills 的技能释放与升级路径固定按“表达式非法即不通过”处理。
condition.on_pass.actions / condition.on_fail.actionslist<\string>否[]—由通用条件解析器读取；EmakiSkills 技能不使用这些字段。
condition.on_fail.block_output / condition.on_fail.messageboolean / string否false / ""—同上，EmakiSkills 技能不使用。

条件无法解析时按“不通过”处理：技能不会释放，升级会被拒绝。释放失败反馈键为 cast.condition_not_met，升级失败反馈键为 upgrade.condition_not_met。

条件文本在求值前会交给 PlaceholderAPI 渲染，因此条件里写的 %...% 必须能被当前安装的 PlaceholderAPI 扩展解析（例如 %emakiskills_level_fireball%）；无法解析的占位符会原样进入表达式求值，按上一条规则判为不通过。

变量与脚本 ​

  • variables：运行时变量，写法与类型见 变量类型。在脚本行、条件与文本中通过 %var.<变量名>% 引用。
  • script：原生脚本块，键位与阶段见 原生脚本系统。
yaml
variables:
  fire_damage:
    type: expression
    value: "10 + %level% * 5"
  battle_cry:
    type: random_text
    lines:
      - "<red>燃烧吧！"
      - "<red>烈焰之力！"

script:
  mode: native          # native / mythic / hybrid
  stop_on_failure: true
  actions:
    cast:
      - 'trigger | damage amount=%var.fire_damage%'
    hit:
      - 'trigger | ignite duration=3s'

resource_costs 资源消耗 ​

yaml
resource_costs:
  - type: "ea-resource"
    target_id: "mana"
    amount: 20
    operation: "consume"
    failure_message: "<red>法力不足。"
字段类型必填默认值取值范围说明
typestring是—ea-resource、attribute-check（别名 ea-attribute-check）、local-resource、auraskills-mana（别名 aura-skills-mana、aura-mana）、mythiclib-mana（别名 mmocore-mana、mythic-mana）资源类型。无法识别的取值会让整条条目被丢弃。
target_idstring否""资源 / 属性 ID对应的本地资源、Attribute 资源或属性 ID。
amountdouble否0≥ 0，负数按 0需要检查或扣除的数量。
operationstring否consumeconsume（扣除）、require（只检查）其他取值按 consume 处理。
failure_messagestring否""MiniMessage，经 PlaceholderAPI 渲染不足时的提示；留空时回退为 target_id 文本。

auraskills-mana 需要安装 AuraSkills，mythiclib-mana 需要安装 MythicLib 或 MMOCore；对应插件不存在时该条目视为不可用，检查直接放行，扣除会被跳过。ea-resource 与 attribute-check 在 EmakiAttribute 不可用时同样直接放行。attribute-check 永远不扣除。

本地资源文件 ​

resources/*.yml 定义 local-resource 使用的资源。资源 ID 取自文件内的 id，与文件名无关。

yaml
id: "mana"
display_name: "<gradient:#4DA6FF:#00BFFF>魔力</gradient>"
max: 100.0
default_current: 100.0
regen_amount: 2.0
regen_interval_ticks: 20
clamp_min: 0.0
clamp_max: 100.0
字段类型必填默认值取值范围说明
idstring是—非空；转小写资源唯一 ID；空值使整份文件被跳过。
display_namestring否idMiniMessage显示名。
maxdouble否100.0≥ 0，负数按 0资源上限。
default_currentdouble否100.0≥ 0，负数按 0玩家首次加载时的当前值。
regen_amountdouble否0.0≥ 0，负数按 0每次自然回复增加的数值。
regen_interval_ticksinteger否0≥ 0，负数按 0回复间隔，单位 tick；0 表示不回复。
clamp_mindouble否0.0≥ 0，负数按 0当前值下限。
clamp_maxdouble否0.0<= 0 时回退 max，否则 ≥ clamp_min当前值上限。

本地资源与其他资源系统

本地资源只保存在技能数据中，不与 EmakiAttribute 自动互通。若已经用 EA 维护同名资源，技能费用应改用 ea-resource，避免并存两套数值。

升级配置 ​

yaml
upgrade:
  enabled: true
  max_level: 5
  gui_template: "upgrade_gui"
  failure_penalty: "none"
  economy:
    enabled: true
    currencies:
      - provider: "vault"
        currency_id: ""
        base_cost: 1200
        cost_formula: "%base_cost% * %target_level%"
        display_name: "<gold>金币</gold>"
  success_rates:
    2: 100.0
    3: 90.0
  levels:
    2:
      materials:
        - item_sources:
            - "minecraft-blaze_powder"
          amount: 2
      actions:
        success:
          - 'send_message text="<yellow>火球术更强了。</yellow>"'
字段类型必填默认值取值范围说明
upgrade.enabledboolean否falsetrue / false是否启用升级。关闭时最大等级为 1。
upgrade.max_levelinteger否1≥ 1，小于 1 被抬升为 1最大等级，也是 level 命令与 API 的夹取上限。
upgrade.gui_templatestring否upgrade_guigui/ 下的模板名升级 GUI 模板。留空、等于 upgrade_gui 或指向不存在的模板时回退到 upgrade_gui（模板不存在时记录警告）。
upgrade.failure_penaltystring否nonenone / downgrade升级失败惩罚。仅 downgrade 会降低一级（最低 1 级）。写 reset 只影响 GUI 文案，不会重置等级。
upgrade.economy.enabledboolean否falsetrue / false是否启用经济消耗。
upgrade.economy.currencieslist<\map>否[]—货币列表，字段见下。
upgrade.success_ratesmap<int,double>否100.0键为 > 0 的整数，值夹取到 0~100按目标等级配置的成功率；未配置的等级取 100。键为非正数或非整数时被跳过。
upgrade.levelsmap<int,map>否{}键为 > 1 的整数映射节点按目标等级覆盖材料、经济、成功率与升级动作。

upgrade.economy.currencies 每项：

字段类型必填默认值取值范围说明
providerstring否auto（转小写）经济提供者名经济来源；留空按 auto 交给 CoreLib 选择。
currency_idstring否""—货币 ID。
base_costdouble否0≥ 0，负数按 0cost_formula 中 %base_cost% 的取值。
cost_formulastring否%base_cost%表达式实际消耗表达式。可按 %base_cost%、%level%（当前等级）、%target_level%、%max_level% 计算；结果 ≤ 0 的条目不计入消耗。
display_namestring否""MiniMessage显示名；留空回退为 currency_id，再回退为 provider。

upgrade.levels.<n> 每项（<n> 为目标等级，必须 > 1）：

字段类型必填默认值取值范围说明
levels.<n>.materialslist<\map>否[]—该等级所需物品材料，字段见下。
levels.<n>.economy.enabledboolean否truetrue / false该等级是否覆盖经济配置为“启用”。
levels.<n>.economy.currencieslist<\map>否[]同 upgrade.economy.currencies该等级的货币覆盖列表；enabled: false 时该等级不收费。
levels.<n>.success_ratedouble否取 upgrade.success_rates夹取到 0~100该等级的成功率覆盖，优先于 upgrade.success_rates。
levels.<n>.actions.successlist<\string>否[]动作管道行升级成功后执行的动作。
levels.<n>.actions.failurelist<\string>否[]动作管道行升级失败后执行的动作（含摇点失败与降级）。

levels.<n>.materials 每项：

字段类型必填默认值取值范围说明
item_sourceslist<\string>否""物品源写法，见 物品匹配器允许的物品源；只取列表中第一项作为物品标识。与同级 matcher 取 AND。
matchermap否无组件 / PDC / Lore 条件非物品源条件。matcher 内不能再写物品源。
amountinteger否1≥ 1，0 按 1需要数量。
optionalboolean否falsetrue / false会被解析，但当前升级判定与扣除流程不读取该字段。
protectionboolean否falsetrue / false会被解析，但当前升级判定与扣除流程不读取该字段。

item_sources 与 matcher 都省略时该材料永不命中，等价于不需要该材料。同类 item_sources 条目在扣除时合并累计；带 matcher 的条目彼此独立。

升级流程与 GUI ​

  • 目标等级 = 当前等级 + 1，并被 max_level 夹取；技能必须已解锁且 upgrade.enabled: true。
  • 顺序为：条件检查 → 触发 SkillPreUpgradeEvent（可取消、可改成功率）→ 检查消耗 → 扣除消耗 → 摇点 → 应用等级或失败惩罚。
  • 消耗在摇点前扣除：摇点失败不会退还已扣除的货币与材料（仅在提交阶段异常时尝试补偿回滚）。
  • 玩家可见反馈来自 lang/<language>.yml 的 upgrade.* 文案键（例如 upgrade.success、upgrade.failed、upgrade.insufficient_funds）。

升级 GUI 由 upgrade.gui_template 指定的模板渲染，槽位 type 决定显示内容：

槽位 type显示内容
skill_display技能图标与名称，替换变量含等级、成功率、失败惩罚文案。
cost_currency货币消耗清单；无消耗时显示 gui.upgrade_cost_free。变量 %currencies%、%currency_count%。
cost_material材料消耗清单，逐项显示“已有/需要”并按是否满足着色；变量 %materials%、%material_count%、%missing_count%。
success_rate成功率标题，变量 %success_rate%。
confirm确认按钮；按未开启升级 / 已满级 / 材料不足 / 可升级切换图标与状态文案。点击后调用与命令同一套升级服务。

GUI 与升级流程共用同一个报价函数（preview）：GUI 渲染时按当前状态展示消耗，点击升级时重新报价并按结果实际扣除，因此在玩家状态未变化时两者数值一致；若在点击前状态已改变（例如材料被用掉），以点击时的重新报价与实际扣除为准，不够则整笔失败且不扣费。

config.yml 中的来源与标签 ​

以下两项在 plugins/EmakiSkills/config.yml 配置，影响技能如何被识别和能装备多少个。

装备技能来源开关 ​

yaml
skill_sources:
  read_lore_skills: true
  read_pdc_skills: true
  require_lore_pdc_match: false
字段类型必填默认值取值范围说明
skill_sources.read_lore_skillsboolean否truetrue / false是否从装备 Lore 读取技能。
skill_sources.read_pdc_skillsboolean否truetrue / false是否从装备 PDC 读取技能。
skill_sources.require_lore_pdc_matchboolean否falsetrue / false严格模式。开启后只保留同一物品、同一槽位下 Lore 与 PDC 的交集，两边不一致的技能不生效。

两侧都关闭、或开启严格模式却只开启了一侧时，配置预检会给出警告。

标签装备数量限制 ​

技能定义里的 tags 命中这里的标签时，玩家最多只能同时装备对应数量：

yaml
skill_tags:
  equip_limits:
    ultimate: 1
    mobility: 2
字段类型必填默认值取值范围说明
skill_tags.equip_limits.<tag>integer否无（不限）> 0，<= 0 或非整数时忽略该键标签最多可同时装备的数量。标签名会被 id 规范化并把 - 转成 _。
tag_limitsmap否无同上旧键名。skill_tags.equip_limits 为空时回退读取该键。

即 tags 含 ultimate 的技能最多装备 1 个，含 mobility 的最多装备 2 个。未列出的标签不受限制。
