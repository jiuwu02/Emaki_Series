EmakiLevel ​

下面依次说明 EmakiLevel 做什么, 怎么安装, 默认会放出哪些文件, 以及默认带哪些等级类型

EmakiLevel 是 Emaki 系列的等级与多经验类型插件. 它负责把长期成长从原版经验里独立出来, 管理主等级, 战斗, 挖矿, 钓鱼, 合成, 炼药, 冶炼, 驯养等多条成长线. 经验来源, 升级需求, 升级奖励, 属性贡献, PlaceholderAPI 占位符, CoreLib Action 和 MythicMobs 掉落都收在这一个插件里

安装方式 ​

服务器只需要安装运行时插件本体:

text
plugins/
├─ EmakiCoreLib-*.jar
└─ EmakiLevel-2.0.0.jar

不要把 emaki-level-api-*.jar 放进服务器 plugins/ 目录. API Jar 只给第三方开发者作为 Maven provided 或 Gradle compileOnly 编译依赖使用; EmakiLevel 插件本体在打包时已经 shade 了自己的 API

可选插件想用哪个就装哪个:

可选插件安装后启用的能力
PlaceholderAPI注册 %emakilevel_*% 占位符
MythicMobs读取 MythicMob 击杀来源, 并注册 emakilevel_exp / elv_exp 这种非实物 Drop (不生成物品, 直接给经验)
EmakiAttribute把等级类型中的 attributes.values 转为 Attribute 属性贡献
EmakiCooking / EmakiForge可通过 CoreLib Action 在配方, 工艺或流程结果中给玩家等级经验

核心能力 ​

  • 多等级类型: 每个 types/*.yml 文件定义一个等级类型, 默认包含 main, combat, mining, fishing, crafting, brewing, smelting, taming 等类型
  • 独立玩家数据: 每名玩家一个 YAML 数据文件, 保存每个等级类型的 level, exp, total_exp 和更新时间
  • 分层升级需求: 升级所需经验按"类型自己写的值 → 分组 → 全局"的顺序一层层查找, 既支持写死某个等级的具体数值, 也支持用公式算
  • 自动/手动升级: 类型可以独立控制自动升级, 手动 /elv levelup, 经济消耗, 材料消耗, 升级奖励和升级动作
  • 经验来源监听: 支持原版击杀, MythicMobs 击杀, 方块破坏, 成熟作物收获, 钓鱼, 合成, 炼药, 冶炼提取和驯养
  • 防刷机制: 可记录玩家放置方块, 避免"放置再破坏"刷经验; 战斗来源可记录最近造成伤害的玩家
  • CoreLib Action: 其他 Emaki 插件或第三方系统可以通过动作增减经验或等级
  • PDC 同步: 把当前等级, 经验, 总经验, 需求经验和进度写进在线玩家实体的持久数据 (PDC, 写在实体上, 重启也不会丢的数据), 方便其他插件读取
  • 属性贡献: 安装 EmakiAttribute 后, 可把等级公式计算出的数值注册为属性贡献

默认配置目录 ​

首次启动会通过 CoreLib Bootstrap (插件启动时的引导流程) 释放默认资源. 运行目录结构如下:

text
plugins/EmakiLevel/
├─ config.yml
├─ requirements.yml
├─ types/
│  ├─ main.yml
│  ├─ combat.yml
│  ├─ mining.yml
│  ├─ example_prestige.yml
│  └─ ...
├─ sources/
│  ├─ combat.yml
│  ├─ block_actions.yml
│  ├─ mythicmobs.yml
│  ├─ example_custom_source.yml
│  ├─ example_block_source.yml
│  └─ ...
├─ gui/
│  ├─ level_gui.yml
│  ├─ top_gui.yml
│  ├─ editor_browser_gui.yml
│  └─ editor_page_gui.yml
├─ lang/
│  ├─ zh_CN.yml
│  └─ en_US.yml
└─ data/
   └─ <uuid>.yml

config.yml 里的 release_default_data: true 控制的是: 缺了默认数据文件时, 要不要把插件内置的 requirements.yml, types/, sources/ 和 gui/ 写出来. 服主已经改过的文件不会因为普通重启就被直接覆盖

基础工作流 ​

照下面的顺序做一遍, 就能把等级系统跑起来:

  1. 安装并启动 EmakiCoreLib 与 EmakiLevel
  2. 查看 plugins/EmakiLevel/types/, 确认需要保留哪些等级类型
  3. 在 requirements.yml 中设置主线和职业等级的经验曲线
  4. 在 sources/*.yml 中配置哪些行为给予哪些类型的经验
  5. 如果需要手动升级消耗, 编辑对应 types/<type>.yml > upgrade.cost
  6. 如果安装了 EmakiAttribute, 在 types/<type>.yml > attributes.values 中配置等级属性公式
  7. 执行 /elv reload 重载配置
  8. 使用 /elv info, /elv debug requirement <type> <level> 和 PlaceholderAPI 检查结果

数据与升级行为概览 ​

玩家数据示例:

yaml
schema_version: 1
uuid: "00000000-0000-0000-0000-000000000000"
name: "PlayerName"
levels:
  main:
    level: 1
    exp: 0.0
    total_exp: 0.0
    updated_at: 1730000000000

升级时, 插件会按如下顺序处理:

  1. 找到等级类型并确认启用
  2. 增加当前等级经验 exp 和总经验 total_exp
  3. 执行 upgrade.actions.gain
  4. 如果允许自动升级, 按 level.max_auto_upgrade_steps 限制循环尝试升级
  5. 每次升级检查需求经验, 最高等级, 手动/自动开关, 经济消耗和材料消耗
  6. 升级成功后扣除需求经验, 提升等级, 发放奖励, 执行 upgrade.actions.success
  7. 升级失败时执行 upgrade.actions.failure, 并把 failure_reason 放入动作上下文
  8. 同步 PDC, 并在 EmakiAttribute 可用时刷新属性贡献
