组件参考 ​

components 节点下所有可用的键, 每个键能填什么, 填上去有什么效果, 逐一列在下面

components 节点下的字段由 ComponentMapper 直接映射到 Minecraft 实体的属性或数据组件. 键名必须和列表逐字一致: 找不到处理器的键会被跳过 (不报错, 不打日志)

随包示例: 首次启动释放的 mobs/example_zombie.yml, 以及插件内置的 mobs/elite_zombie.yml, mobs/bone_lord.yml 都用到了下表中的字段, 你可以直接对照阅读

下表中的"必填"一律是"否": 整个 components 可以默认不写, 没写进去的键不会被应用. "默认值"一律是"—", 表示不写时保留原版或实体自己的状态. "取值范围"写"—"表示源码没有做校验 (数值会原样写入, 越界会怎样由原版属性或实体 API 决定)

生成与刷新的规则 ​

  • 仅生成时应用 (只在刷出的那一刻生效): absorption, freeze_ticks, fire_ticks, potion_effect, 以及全部装备类字段 (helmet, chestplate, leggings, boots, main_hand, off_hand, equipment). 这些是消耗性状态, /emakimobs reload 触发的刷新不会重置它们, 也不会补回损坏或已经失去的装备
  • max_health 特殊处理: 刷出时先应用上限, 然后立刻把血量补满; 刷新时保留当前血量, 再按新上限截断 (上限升高不会回血, 上限降低会把血量截断到新上限)
  • 其余组件 (属性类与外观行为类) 每次刷新都会按配置重新写入

属性类字段 ​

字段类型必填默认值取值范围说明
max_healthdouble否——最大生命值 (原版属性 MAX_HEALTH)
movement_speeddouble否——移动速度 (原版僵尸约 0.23, 玩家 0.1)
attack_damagedouble否——近战攻击的伤害
attack_speeddouble否——攻击的速度
attack_knockbackdouble否——攻击时把目标推开的力度
follow_rangedouble否—— (格)追踪目标的最远距离
knockback_resistancedouble否—0.0–1.0 (原版属性范围)抗击退的值, 1.0 就是完全免疫击退
armordouble否——护甲值
armor_toughnessdouble否——护甲韧性
luckdouble否——幸运值
flying_speeddouble否——飞行速度 (只对会飞的生物有用)
scaledouble否——实体渲染的缩放倍率, 1.0 是原版大小
step_heightdouble否——能直接跨上去的方块高度
jump_strengthdouble否——跳跃强度 (马这类可骑乘生物用)
safe_fall_distancedouble否——多高摔下来不会受伤
fall_damage_multiplierdouble否——摔落伤害的倍率
burning_timedouble否——着火后能烧多久的倍率
explosion_knockback_resistancedouble否——爆炸击退抗性
spawn_reinforcementsdouble否—0.0–1.0 (原版属性范围)僵尸召唤援军的概率
oxygen_bonusdouble否——水下呼吸的加成
water_movement_efficiencydouble否——水中移动的效率
movement_efficiencydouble否——地面移动的效率

NOTE

以上都是原版实体属性 (Attribute). 如果目标实体身上没有这个属性, 该项会被忽略 (比如给僵尸写 flying_speed)

外观与行为类字段 ​

字段类型必填默认值取值范围说明
custom_namestring否—任意字符串实体展示的名字, 支持 MiniMessage 格式 (它和 display_name 字段不同, 这里会真正改写实体名牌)
custom_name_visibleboolean否—true / false是否始终显示名牌; 填 false 就只在靠近时显示
persistentboolean否—true / false是否让它一直留存 (不会因为区块里没有玩家而自然消失)
silentboolean否—true / false是否屏蔽这只生物的音效
invulnerableboolean否—true / false是否无敌 (免疫所有伤害)
no_aiboolean否—true / false填 true 时关掉 AI (生物不再移动和攻击)
glowingboolean否—true / false是否发光 (显示轮廓)
gravityboolean否—true / false是否受重力影响
collidableboolean否—true / false是否参与实体之间的碰撞 (推挤)
fire_immuneboolean否—true / false是否免疫火焰伤害; 填 true 时会写入实体 PDC, 并取消着火与火焰/岩浆类的伤害事件
visual_fireboolean否—true / false是否强制显示着火的外观效果 (不会产生实际伤害)
absorptiondouble否—— (点)初始的伤害吸收量 (黄心); 只在刷出时应用
freeze_ticksint否—— (tick)初始冰冻多少 tick (1 tick = 1/20 秒); 只在刷出时应用
fire_ticksint否—— (tick)初始着火多少 tick; 只在刷出时应用

掉落类字段 ​

字段类型必填默认值取值范围说明
loot_tablestring否—<命名空间>:<路径> 或裸路径 (会自动补 minecraft:)设置这只生物使用的原版/数据包掉落表: 这个值交给 Bukkit.getLootTable 解析, 查得到才会写入实体 (插件不注册数据包, 所以自定义命名空间的值查不到, 这时不报错, 也不做任何事). 它和 loot_tables/*.yml 没有关系
can_pick_up_lootboolean否—true / false这只生物能不能捡起地上的物品
remove_when_farboolean否—true / false玩家走远后是否自动移除 (会覆盖 persistent)

自定义掉落表会替换原版掉落

loot_tables/<mob_id>.yml 只要同名文件存在就生效 (和 components 有没有写 loot_table 无关); 生效后, 死亡时会执行 event.getDrops().clear(), 清空全部原版掉落, 改由这张表的池产出 (击杀经验仍按 experience 保留)

  • 想保留原版掉落, 就不要给这只生物创建同名 YAML 掉落表
  • 两者互不影响: loot_table 只管原版/数据包掉落表本身; 写 loot_table: "minecraft:entities/zombie" 会设置原版表, 但同名 YAML 表存在时原版掉落还是会被替换

装备类字段 ​

字段类型必填默认值取值范围说明
main_handItemConfig 或材质名否—见下方 ItemConfig主手拿的物品 (只在刷出时应用)
off_handItemConfig 或材质名否—同上副手拿的物品 (只在刷出时应用)
helmetItemConfig 或材质名否—同上头盔 (等同于 equipment.head, 只在刷出时应用)
chestplateItemConfig 或材质名否—同上胸甲 (等同于 equipment.chest, 只在刷出时应用)
leggingsItemConfig 或材质名否—同上腿甲 (等同于 equipment.legs, 只在刷出时应用)
bootsItemConfig 或材质名否—同上靴子 (等同于 equipment.feet, 只在刷出时应用)
equipmentmap否—键为槽位名, 值为 ItemConfig 或材质名用一个节点一次性配置多个槽位 (只在刷出时应用)

equipment 下的槽位名支持以下写法 (大小写不敏感):

槽位可用键名
主手main_hand, hand
副手off_hand
头部helmet, head
胸部chestplate, chest
腿部leggings, legs
脚部boots, feet

ItemConfig 支持这些字段:

字段类型必填默认值取值范围说明
itemstring否—原版材质名 (大小写不敏感, 可带 minecraft: 前缀)只接受"能当物品用"的原版材质; 匹配失败时这个槽位保持原样
drop_chancedouble否— (保持原版默认掉落率)0.0–1.0死亡时掉落这件装备的概率; 0.0 就是不掉落. 本地没有做钳制, 越界取值会怎样由原版装备 API 决定
yaml
components:
  main_hand:
    item: "minecraft:iron_sword"
    drop_chance: 0.05
  helmet:
    item: "minecraft:iron_helmet"
    drop_chance: 0.0
  equipment:
    legs:
      item: "minecraft:iron_leggings"
      drop_chance: 0.0
    # 只指定物品时可以省略 ItemConfig, 直接写材质名
    feet: "minecraft:iron_boots"

药水效果字段 ​

字段类型必填默认值取值范围说明
potion_effectstring 或 string list否—冒号分隔的效果串, 见下表生物刷出时自带的药水效果 (只在刷出时应用). 只有一条效果时可以直接写字符串, 多条就写成字符串列表

每条效果是一个冒号分隔的字符串:

text
<效果类型>:<持续 tick>[:<效果等级>]
段必填说明
效果类型是原版效果 ID, 大小写不敏感 (speed, regeneration, fire_resistance 等), 按 minecraft: 命名空间查表
持续 tick是持续的时间, 单位是 tick; 必须能解析成整数
效果等级否省略时是 0 (也就是 I 级), 1 是 II 级
yaml
components:
  potion_effect:
    - "speed:99999:1"
    - "regeneration:600"
  # 单条效果也可以直接写成字符串
  # potion_effect: "fire_resistance:1200"

不支持映射写法

potion_effect 只解析上面那种冒号分隔的字符串. 写成 - type: SPEED / duration: / amplifier: 这类映射不会报错, 但整条效果会被丢掉. ambient, particles, icon 都不是可配置项. 效果类型认不出来, 缺少持续时间, 数字解析不了时, 该条同样会被跳过 (不报错, 不打日志)
