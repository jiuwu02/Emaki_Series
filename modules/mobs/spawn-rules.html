刷新规则 ​

刷新规则文件位于 plugins/EmakiMobs/spawn_rules/*.yml，每个文件可包含多条规则，通过 rules: 列表定义。文件缺失、rules 缺失或不是列表时，该文件不产生任何规则。首次启动释放的默认规则是 spawn_rules/overworld_elites.yml（一条 natural 规则）。

文件结构 ​

yaml
rules:
  - mob_id: <生物 id>
    type: <刷新类型>
    # 各类型专属字段…

只接受两种 type ​

当前加载器只认 type: natural 与 type: autonomous。写 structure、biome、player_relative、day_interval、custom 等值不会报错，而是被记录为 Unknown spawn type 并静默跳过整条规则；缺 mob_id 或 type 时同样跳过并打 WARN。

内置参考文件 spawn_rules/overworld.yml 里有两条规则不会被加载

该文件位于插件 jar 内，不会自动释放到 plugins/EmakiMobs/spawn_rules/（首次启动释放的是 overworld_elites.yml）。它含三条规则：natural（elite_zombie）有效，而 type: structure（bone_lord）与 type: biome（jungle_stalker）会命中上面的未知类型分支被静默跳过。照抄该文件时请按本文的 natural / autonomous 写法改写这两条。

natural — 原版事件拦截 ​

在满足条件时按概率把原版刷新的生物替换为自定义生物。自然刷新走 PreCreatureSpawnEvent（在实体创建之前拦截）；其余非 NATURAL、非 SPAWNER 的刷新来源走 CreatureSpawnEvent 并取消原刷出。

yaml
- mob_id: elite_zombie
  type: natural
  biomes:                    # 限定生物群系列表；留空则不限
    - plains
    - forest
  y_range: [-64, 50]         # 仅在此 Y 范围内替换
  light_level_max: 7         # 光照等级上限（含）
  replacement_chance: 0.08   # 替换概率，0.0–1.0
  max_nearby: 3              # 64 格内同 id 生物上限；0 = 不限
  count:
    min: 1
    max: 1
字段类型必填默认值取值范围说明
mob_idstring是无已加载的生物定义 id要刷出的生物；非字符串或缺失时整条规则被跳过。id 未注册时不刷出。
typestring是无natural固定值。
worldsstring list否[]（不限）世界名（World#getName）限定生效世界。
biomesstring list否[]（不限）群系键，可带命名空间（取 : 之后一段并转小写）限定群系；无法识别的名字打 WARN 后忽略该条，规则其余部分仍生效。
y_rangeint list [min, max]否[-64, 320]按下标读取列表：第 1 项为 min、第 2 项为 max，缺项用默认值刷出位置的 Y 范围（含端点）。
light_level_maxint否150–15刷出位置综合光照等级不超过该值才触发；默认 15 等价于不限制。
replacement_chancedouble否1.0—命中条件后替换的概率：0.0 永不替换，≥ 1.0 必定替换（未做钳制）。
max_nearbyint否0≥ 0；0 = 不限64 格内同 id 受管生物达到该数量时不再触发。
count{min, max}否{1, 1}min ≤ max每次触发刷出的数量（随机区间，含端点）。min > max 会在触发时抛出异常，使该次替换失败。
conditionsection否无CoreLib 条件块额外条件。没有玩家上下文，因此不能写玩家占位符（与 autonomous 不同）。

autonomous — 自主定时刷新 ​

完全脱离原版刷新事件，由自己的调度器驱动。trigger 决定调度方式。候选位置由「以玩家为中心、distance 距离上的随机角度」生成，最高尝试 6 次，要求该位置上方可通行、下方为固体方块，因此不保证每次尝试都能刷出。

yaml
- mob_id: elite_zombie
  type: autonomous
  trigger: interval
  interval_ticks: 1200
  worlds:
    - world
  biomes:
    - plains
  distance:
    min: 16
    max: 64
  max_nearby: 4
  max_global: 10
  count:
    min: 1
    max: 2

四种 trigger ​

trigger调度方式相关字段
interval全局固定周期（启动后 1 tick 起算），每轮逐个扫描所有在线玩家，对每名玩家各尝试一次interval_ticks、worlds、max_global
player_follow全局固定周期，每轮随机选一名在线玩家尝试一次interval_ticks、worlds、max_global
day_interval每 20 tick 检查一次各世界游戏日计数（按世界分别记录上次触发日），到点时为该世界所有玩家各尝试一次interval_days、on_day_start、worlds、max_global
cron按真实系统时间的 Cron 触发，每次为每个在线玩家各尝试一次cron、worlds、max_global

trigger 值不区分大小写。cron 使用 6 段 Quartz 格式，写法见 CoreLib 表达式 · Cron 表达式；表达式为空或无法解析时只打一条警告，该规则永不触发。

autonomous 字段 ​

字段类型必填默认值取值范围说明
mob_idstring是无已加载的生物定义 id要刷出的生物；非字符串或缺失时整条规则被跳过。
typestring是无autonomous固定值。
triggerstring是无interval / player_follow / day_interval / cron（大小写不敏感）调度方式。缺失或未知时整条规则被跳过并打 WARN。
interval_tickslong否600≥ 1（tick）interval / player_follow 的调度周期。
interval_daysint否1≥ 1（游戏日）day_interval 的间隔游戏日数。
on_day_startboolean否falsetrue / falsetrue 时只在该世界时间 < 1000（刚天亮）触发；false 时计时到达即触发。
cronstring否""6 段 Quartz 表达式trigger: cron 的表达式；为空时打一条警告且该规则永不触发。
worldsstring list否[]（不限）世界名限定生效世界。
biomesstring list否[]（不限）群系键（同 natural）限定刷出点群系。
structuresstring list否[]（不限）NamespacedKey，如 minecraft:stronghold限定刷出点所在区块的结构包围盒内；未知结构打 WARN 后忽略该条。
y_rangeint list [min, max]否[-64, 320]同 natural刷出位置的 Y 范围（含端点）。
light_level_maxint否150–15综合光照上限；仅当该值小于 15 时才检查，默认 15 完全不检查光照。
time_of_daystring否anyany / day（1000–12999）/ night（≥ 13000 或 < 1000）（大小写不敏感）限定时段；未知取值等同 any。
require_surfaceboolean否falsetrue / falsetrue 时要求刷出点天光为 15。
distance{min, max}否{16, 64}≥ 0（格）距玩家的刷新距离范围（含端点）；min ≥ max 时固定使用 min。
max_nearbyint否0≥ 0；0 = 不限64 格内同 id 受管生物上限。
max_globalint否0≥ 0；0 = 不限全服（所有世界）同 id 上限；达到上限时该轮整体跳过。
count{min, max}否{1, 1}≥ 1每次刷出数量（随机区间，含端点）；min ≥ max 时固定使用 min。
conditionsection否无CoreLib 条件块额外条件；以触发该次尝试的玩家为上下文，可渲染 PlaceholderAPI 占位符。

与 natural 的差别

natural 的 condition 没有玩家上下文；autonomous 的 condition 会用当前尝试的玩家渲染占位符。两者的 count、distance 也都在 min 与 max 相等时退化为固定值。
