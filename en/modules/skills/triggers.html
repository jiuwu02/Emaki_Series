Triggers ​

Trigger configuration covers when active skills may be cast, which game events fire passive skills, how conflicts between triggers are handled, and how to set up cast mode

A trigger is the rule for "when a skill fires". EmakiSkills splits them into active triggers and passive triggers

  • Active triggers are global slot triggers. You bind a skill to a trigger slot in the GUI, then cast it while cast mode is enabled
  • Passive triggers are declared in skill definitions through trigger_type: passive and passive_triggers, and fire automatically when their event happens
text
Active:  the player binds a skill to right_click → right click while in cast mode
Passive: the definition says passive_triggers: [attack] → fires on a successful hit

The registry is built from two parts: the plugin's built-in default definitions plus same-id overrides from config.yml under triggers / passive_triggers. Config therefore only supplies the display name, enabled flag, and conflict declarations; if you want a trigger id that is not in the built-in list (for example consume), you must register it in config explicitly, otherwise it is dropped at dispatch time without an error

consume must be registered in config.yml yourself

The listener dispatches consume for PlayerItemConsumeEvent (eating or drinking), but consume is neither a built-in default trigger nor present in the bundled config.yml > passive_triggers. Unregistered triggers are dropped at dispatch time, so writing passive_triggers: [consume] alone has no effect and raises no error

To enable it, add this section under config.yml > passive_triggers first:

yaml
passive_triggers:
  consume:
    display_name: "[Consume]"
    enabled: true
    incompatible_with: []

Passive trigger settings ​

yaml
passive_trigger_settings:
  # Interval of the timer check, in ticks; values below 1 are treated as 1
  timer_interval_ticks: 20
  # Combo timeout, in ticks; the combo counter resets when no attack arrives in time
  combo_timeout_ticks: 60
FieldTypeRequiredDefaultValuesDescription
passive_trigger_settings.timer_interval_ticksintegerNo20≥ 1, values below 1 become 1Check interval of the timer passive trigger, in ticks
passive_trigger_settings.combo_timeout_ticksintegerNo60≥ 1, values below 1 become 1Combo state timeout for combo_attack, in ticks; a longer gap without attacking resets the counter

Cron passive trigger ​

When a skill definition sets cron_expression, a passive trigger with the ID cron_<skill id> is registered automatically and added to that skill's passive_triggers; you do not write it by hand. The expression uses the same format as spawn_rules' cron, see CoreLib expressions - Cron. cron_max_executions caps the total number of firings; 0 means unlimited. An invalid expression logs a warning and skips that skill

Trigger conflict resolution ​

Conflicts are declared with incompatible_with, and the relation is mutual:

  • Every trigger conflicts with itself (one trigger cannot carry two skills)
  • Conflicting triggers cannot both hold a skill (for example left_click and shift_left_click)

The conflict matrix is built while loading config, so the plugin checks conflicts automatically when a player binds in the GUI. The built-in defaults declare four pairs: left_click ↔ shift_left_click and right_click ↔ shift_right_click

Cast mode ​

To cast an active skill, enter cast mode first

yaml
cast_mode:
  # The entry key is fixed to F; enabled only controls the F-key toggle, it is not a master switch
  entry_key: "f"
  # With false, F restores the vanilla hand swap while the command and GUI can still toggle cast mode
  enabled: true
  # Whether the previous cast mode state is restored when the player rejoins
  restore_last_state_on_join: true
FieldTypeRequiredDefaultValuesDescription
cast_mode.entry_keystringNo"f"Always fEntry key. The config record forces f while being constructed, so any other configured value has no effect
cast_mode.enabledbooleanNotruetrue / falseWhether the F key toggles cast mode. With false, F restores the vanilla hand swap while the command and GUI still toggle cast mode
cast_mode.restore_last_state_on_joinbooleanNotruetrue / falseWhether the previous cast mode state is restored after rejoining
  • The F key toggles cast mode by default
  • Active triggers only listen to server-visible actions (left/right click, Q, number keys) while cast mode is on; those actions dispatch nothing when cast mode is off
  • While cast mode is on, the action bar shows slot state; templates and variables are in Action bar

Configuration examples ​

Active skill ​

yaml
id: fireball
trigger_type: active
display_name: '<red>Fireball'
cooldown_ticks: 100
global_cooldown_ticks: 20
resource_costs:
  - type: ea-resource
    target_id: mana
    amount: 20
    operation: consume

Bind it to the right_click slot in the GUI, then right click while in cast mode to release it

Passive skill ​

yaml
id: thorns_aura
trigger_type: passive
passive_triggers:
  - damaged_by_entity
display_name: '<yellow>Thorns Aura'
cooldown_ticks: 40

It fires when you are damaged by an entity, limited by cooldown_ticks

Timed passive ​

yaml
id: regen_aura
trigger_type: passive
passive_triggers:
  - timer
display_name: '<green>Regen Aura'
cooldown_ticks: 0
resource_costs:
  - type: ea-resource
    target_id: mana
    amount: 5
    operation: consume

It fires automatically at the global timer_interval_ticks interval

Combo passive ​

combo_attack attaches combo_count (the current combo count) to the trigger invocation, so your skill can use it in conditions or variables. The bundled skills/example_combo_skill.yml reads it from a condition block:

yaml
id: combo_finisher
trigger_type: passive
passive_triggers:
  - combo_attack
condition:
  type: all_of
  entries:
    - "%combo_count% >= 5"
cooldown_ticks: 100

The %...% inside a condition expression must be resolvable by PlaceholderAPI; see Definitions - The condition block. combo_attack uses the entity just hit as both target and area centre
