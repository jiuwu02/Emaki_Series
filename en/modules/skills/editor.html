Definition Editor ​

This page covers the EmakiSkills in-game definition editor: how to open it, how the browser and editor GUIs work, which definitions you can edit, how edits are validated and saved, and the edit-backups mechanism

The editor is for server owners and config editors: browse, create, modify, and delete definition files under skills/ and resources/ without leaving the game. What each skill or resource field means still belongs to Skill definitions; this page only covers the editor itself

Opening the editor ​

CommandEffect
/eskills editOpen the definition browser, listing every category and definition file
/eskills edit <id>Open the editor page of that definition directly; ids tab-complete across skills and local resources

The permission is emakiskills.edit or emakiskills.admin (default op), and the command is players only: running it from the console replies with a player-only notice. An unknown id replies "Could not open the editor for %id%"

What you can edit ​

The browser groups definitions by category; each category maps to a directory:

CategoryLocationNew-file skeleton
Skill definitionsskills/*.ymlid, display_name, description, icon_material, trigger_type, cooldown_ticks, global_cooldown_ticks, tags, tab_tags, conflicting_skills, required_skills, show_in_slots, ui_category, sort_order, enabled, resource_costs, variables, script, upgrade
Local resourcesresources/*.ymlid, display_name, max, default_current, regen_amount, regen_interval_ticks, clamp_min, clamp_max
  • A file's id comes from the id key inside it, falling back to the file name without the extension.
  • New definitions are prefilled from the skeleton above; the skill skeleton starts with an empty script action pipeline in mode: native and a disabled upgrade block with max_level: 1. Edit the fields from there.
  • The bundled example skills (example_*.yml) and the example script skill are ordinary definition files too: browse, edit, or delete them like any other

Definition browser (editor_browser_gui.yml) ​

/eskills edit with no argument opens the browser: definition files across categories, one screen per page. The template is gui/editor_browser_gui.yml, a 5-row layout (row 1 back/close, rows 2-4 content, row 5 paging and create):

Slot keyTypeDefault positionMeaning
doc_entryfield_entrycontent rows 2-4Definition entry; left-click opens the editor page, right-click deletes (double confirmation, auto-backup first)
backback0Back / close the browser
closeclose8Close the browser
page_prevpage_prev36Previous page
page_infopage_info38Page number and definition count (%current_page%, %total_pages%, %menu_title%, %entry_count%)
page_nextpage_next40Next page
new_docnew_doc42Create a definition: pick a category, then type the new id in chat
borderfillerremaining slotsDecorative filler, not interactive

Creation rules: ids may only contain lowercase letters, digits, and underscores (e.g. my_skill); an illegal id, a duplicate id, or a category that does not support creation is rejected with a message (both categories support create and delete). Deleting takes two clicks: the first "Delete" opens the confirmation screen, "Confirm delete" executes, and "Cancel" leaves everything untouched

Editor page (editor_page_gui.yml) ​

Clicking a definition (or /eskills edit <id>) opens its editor page. Every submenu shares gui/editor_page_gui.yml; the title follows the current submenu and fields render into the content grid:

Slot keyTypeDefault positionMeaning

back_parentback_parent0Back to the parent menu
back_homeback_home1Back to the editor home menu
closeclose8Close the editor

page_infopage_info40Page number and entry count

Deep skill fields get their own submenus: cast condition, skill variables, skill script (with cast/hit/miss/fail action phases), upgrade settings (including upgrade economy), and resource cost entries. Field interactions (exactly what the in-game hints say):

Field shapeInteraction
ToggleLeft-click switches on/off, right-click resets
EnumLeft-click cycles to the next value, right-click resets
NumberLeft-click prompts for a value in chat, right-click resets
TextLeft-click prompts for text in chat, right-click resets
SubmenuLeft-click enters
ListLeft-click views; sequence lists: left-click adds a row, Shift+left-click edits an entry, right-click removes the last row, Shift+right-click clears
MapLeft-click edits an entry (type key=value in chat), right-click resets the whole node

Type cancel in chat to abort an input prompt; a malformed map entry is rejected with a key=value hint

Validation and saving ​

  • Every field edit is validated immediately: the YAML must parse, the definition id cannot be empty or change (id_changed), and the content must be readable by the matching parser (the skill parser for skills, the resource parser for local resources). Skills with enabled: false skip the parse check, so you can disable one first and edit it at your own pace.
  • On success the chat says "Successfully modified %item%" with an experience-orb sound; on failure it reports the reason with a villager-no sound and the edit does not take effect. Parse failures (definition_parse_failed) log the details to console.
  • Edits accumulate in the editing session and the plugin writes them to disk at its flush points: before any /eskills reload and before the plugin shuts down, pending edits are flushed first. Run /eskills reload to persist and apply changes right away.
  • Creating and deleting reload the module immediately, so those take effect at once.
  • If an external program changed the file underneath you, the write is rejected by a revision check (a conflict is reported) instead of silently overwriting it; an oversized definition document is also rejected

edit-backups ​

Before every write to disk, the previous contents of the file are backed up to:

text
plugins/EmakiSkills/edit-backups/<millisecond timestamp>/<file name>.yml

Deletion works the same way: the file is copied into edit-backups before it is removed from its directory, which is why the confirmation screen says the action cannot be undone but a backup is written to edit-backups first. If you delete the wrong definition, copy the file back from the backup directory. Backups go into per-timestamp folders and never overwrite each other; clean them up periodically
