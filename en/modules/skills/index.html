EmakiSkills ​

EmakiSkills (the skills module) covers how skills unlock, how they go into skill slots, when a cast is allowed, what it costs, how leveling works, and where your data is stored

Who runs the skill effect after a cast depends on the script.mode switch: native uses the built-in script system (script_engine.default_mode is native by default and needs no external plugin), mythic hands execution to MythicMobs, and hybrid runs both

Top-level config.yml keys ​

The top level of config.yml stays short: only the version, language, and default-data release switches plus one slots block. The remaining keys live on the feature pages below

yaml
# version is maintained by resource syncing and is not a feature switch
version: "3.0.0"
# Language file name, resolved as lang/<language>.yml
language: "zh_CN"
# Whether to release the plugin's bundled default skill data at startup
release_default_data: true

slots:
  # Default skill slot count; values below 1 are treated as 1
  default_count: 3

Config precheck

Loading checks that config.yml, skills/, resources/, and gui/ exist and parse, and compiles script action lines to report diagnostics. A warning is raised when both skill_sources sides are off, or when require_lore_pdc_match is on with only one side enabled

Skill types ​

Active skills ​

Active skills are cast by the player, by hand, through a skill slot, command, GUI, or cast mode. What you usually configure:

  • MythicMobs skill ID
  • Cooldown
  • Global cooldown
  • Resource consumption
  • Condition checks
  • Skill level and parameters

Passive skills ​

Passive skills need no input from the player; game events fire them on their own, such as attack, being hit, kill, movement, or block. All you do is configure the trigger and conflict handling

Cast mode ​

Cast mode is a switch: the player can only cast while in the right state. Because the client-side G key cannot be observed natively by the server, skill triggers rely on server-visible behavior such as commands, GUI, F key item swap, or interaction events

Resource system ​

Skills use several kinds of resources; each one can either be consumed or only checked:

  • ea-resource: consume Attribute resources through the EmakiAttribute bridge
  • attribute-check: verify a certain attribute meets the requirement. Alias: ea-attribute-check
  • local-resource: use EmakiSkills' local resource definitions
  • auraskills-mana: use AuraSkills mana. Aliases: aura-skills-mana, aura-mana
  • mythiclib-mana: use MythicLib / MMOCore mana. Aliases: mmocore-mana, mythic-mana

Typical cast flow ​

  1. The player triggers an active or passive skill
  2. Skills checks whether the player owns the skill
  3. Skills checks skill level, slot, trigger, and conditions
  4. Skills checks cooldown and global cooldown
  5. Skills checks and consumes resources
  6. Skills runs the built-in script actions, the MythicMobs skill, or both, according to script.mode
  7. Skills writes cooldown, statistics, or upgrade progress
  8. Skills sends feedback to the player

When a cast fails, the player-facing message comes from keys such as cast.* in lang/<language>.yml; the internal reason key is never shown to players
