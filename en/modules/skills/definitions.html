Skill Definitions ​

Skill files live in plugins/EmakiSkills/skills/*.yml. EmakiSkills defines the management layer of a skill, while effects run through the native script system or MythicMobs. Local resource definitions live in plugins/EmakiSkills/resources/*.yml.

Loading rules ​

  • One file loads exactly one skill. A blank id makes the whole file be skipped and recorded as a loader issue.
  • A skill with enabled: false never enters the registry, which is the same as the skill not existing.
  • Skill ids are normalized to lower case; ids inside list fields are id-normalized with - folded to _.
  • List fields accept alias keys (see the table); when both are present their entries are merged in order and de-duplicated.

Top-level fields ​

id: "fireball"
enabled: true
display_name: "<red>Fireball"
description:

icon_material: "fire_charge"
mythic_skill: "EmakiFireball"
trigger_type: "active"
cooldown_ticks: 100
global_cooldown_ticks: 20

The condition block ​

Casting and upgrading share the same condition block. Condition text is rendered through PlaceholderAPI before evaluation.

yaml
condition:
  type: "all_of"
  entries:
    - "%player_level% >= 5"
    - "%emakiskills_level_fireball% >= 2"
FieldTypeRequiredDefaultValuesDescription
conditionmapNonone—Must be a mapping node; without entries the block counts as no condition at all.
condition.typestringNoall_ofall_of, any_of, none_of, at_least, exactlyHow multiple conditions combine.
condition.entrieslist<\string>No[]Expression stringsCondition expressions; omitting the key leaves the whole block empty.
condition.required_countintegerNo0≥ 0Match threshold for the at_least / exactly combine modes.
condition.invalid_as_failurebooleanNotruetrue / falseRead by the shared condition parser; EmakiSkills' cast and upgrade paths always treat an unparseable expression as "not passed".
condition.on_pass.actions / condition.on_fail.actionslist<\string>No[]—Read by the shared condition parser; EmakiSkills skills do not use them.
condition.on_fail.block_output / condition.on_fail.messageboolean / stringNofalse / ""—Same as above; not used by EmakiSkills skills.

A condition that cannot be parsed counts as "not passed": the skill is not cast and the upgrade is rejected. The cast failure key is cast.condition_not_met and the upgrade failure key is upgrade.condition_not_met.

Condition text is handed to PlaceholderAPI before evaluation, so every %...% in it must be resolvable by an installed expansion (for example %emakiskills_level_fireball%). An unresolvable placeholder reaches the expression as-is and, per the rule above, counts as not passed.

Variables and scripts ​

  • variables: runtime values; syntax and types are in Variable types. Script lines, conditions, and text read them as %var.<name>%.
  • script: the native script block; keys and phases are in Native scripting.
yaml
variables:
  fire_damage:
    type: expression
    value: "10 + %level% * 5"
  battle_cry:
    type: random_text
    lines:
      - "<red>Burn!"
      - "<red>Flame power!"

script:
  mode: native          # native / mythic / hybrid
  stop_on_failure: true
  actions:
    cast:
      - 'trigger | damage amount=%var.fire_damage%'
    hit:
      - 'trigger | ignite duration=3s'

resource_costs ​

yaml
resource_costs:
  - type: "ea-resource"
    target_id: "mana"
    amount: 20
    operation: "consume"
    failure_message: "<red>Not enough mana."
FieldTypeRequiredDefaultValuesDescription
typestringYes—ea-resource, attribute-check (alias ea-attribute-check), local-resource, auraskills-mana (aliases aura-skills-mana, aura-mana), mythiclib-mana (aliases mmocore-mana, mythic-mana)Resource type. An unrecognized value makes the whole entry be dropped.
target_idstringNo""Resource / attribute idThe local resource, Attribute resource, or attribute id involved.
amountdoubleNo0≥ 0, negatives become 0Amount to check or deduct.
operationstringNoconsumeconsume (deduct), require (check only)Any other value is treated as consume.
failure_messagestringNo""MiniMessage, rendered through PlaceholderAPIMessage shown when the check fails; when blank it falls back to the target_id text.

auraskills-mana requires AuraSkills and mythiclib-mana requires MythicLib or MMOCore; when the plugin is absent the entry counts as unavailable, so the check passes and the deduction is skipped. ea-resource and attribute-check behave the same way when EmakiAttribute is unavailable. attribute-check never deducts.

Local resource files ​

resources/*.yml defines the resources used by local-resource. The resource id comes from the id key, not the file name.

display_name: "<gradient:#4DA6FF:#00BFFF>Mana</gradient>"
max: 100.0
default_current: 100.0
regen_amount: 2.0
regen_interval_ticks: 20
clamp_min: 0.0
clamp_max: 100.0

display_namestringNoidMiniMessageDisplay name.

default_currentdoubleNo100.0≥ 0, negatives become 0Starting value the first time a player is loaded.
regen_amountdoubleNo0.0≥ 0, negatives become 0Amount added by each natural regeneration step.

Local resources versus other resource systems

Local resources are stored only in skill data and are not synchronized with EmakiAttribute. If EmakiAttribute already maintains a resource of the same name, skill costs should use ea-resource so the two never diverge.

Upgrade configuration ​

yaml
upgrade:
  enabled: true
  max_level: 5
  gui_template: "upgrade_gui"
  failure_penalty: "none"
  economy:
    enabled: true
    currencies:
      - provider: "vault"
        currency_id: ""
        base_cost: 1200
        cost_formula: "%base_cost% * %target_level%"
        display_name: "<gold>Coins</gold>"
  success_rates:
    2: 100.0
    3: 90.0
  levels:
    2:
      materials:
        - item_sources:
            - "minecraft-blaze_powder"
          amount: 2
      actions:
        success:
          - 'send_message text="<yellow>The fireball grows stronger.</yellow>"'
FieldTypeRequiredDefaultValuesDescription
upgrade.enabledbooleanNofalsetrue / falseWhether upgrades are enabled. When off, the maximum level is 1.
upgrade.max_levelintegerNo1≥ 1, values below 1 become 1Maximum level, also the clamp used by the level command and the API.
upgrade.gui_templatestringNoupgrade_guiA template name under gui/Upgrade GUI template. Blank, equal to upgrade_gui, or pointing at a missing template all fall back to upgrade_gui (a warning is logged when the template is missing).
upgrade.failure_penaltystringNononenone / downgradeFailure penalty. Only downgrade lowers the level by one (never below 1). Writing reset only changes the GUI text; it does not reset the level.
upgrade.economy.enabledbooleanNofalsetrue / falseWhether currency costs are charged.
upgrade.economy.currencieslist<\map>No[]—Currency list, fields below.
upgrade.success_ratesmap<int,double>No100.0Keys are integers > 0; values are clamped to 0-100Success rate by target level; unlisted levels use 100. Non-positive or non-integer keys are skipped.
upgrade.levelsmap<int,map>No{}Keys are integers > 1 with mapping nodesPer-target-level overrides for materials, economy, success rate, and upgrade actions.

FieldTypeRequiredDefaultValuesDescription

Upgrade flow and GUI ​

  • Target level = current level + 1, clamped by max_level; the skill must be unlocked and upgrade.enabled must be true.
  • Order: condition check → SkillPreUpgradeEvent (cancellable, success rate may be replaced) → cost check → charge → roll → apply the level or the failure penalty.
  • Costs are charged before the roll, so a failed roll does not refund the currency and materials already charged (compensation is only attempted when the commit stage throws).
  • Player-visible feedback comes from the upgrade.* keys in lang/<language>.yml (for example upgrade.success, upgrade.failed, upgrade.insufficient_funds).

The upgrade GUI is rendered from the template named by upgrade.gui_template; each slot's type decides its content:

Slot typeContent
skill_displaySkill icon and name, with level, success rate, and failure-penalty text as replacements.
cost_currencyCurrency cost list; shows gui.upgrade_cost_free when there is no cost. Replacements %currencies%, %currency_count%.
cost_materialMaterial cost list, one line per item showing "have/required" and colored by whether it is satisfied. Replacements %materials%, %material_count%, %missing_count%.
success_rateSuccess-rate title, replacement %success_rate%.
confirmConfirmation button; its icon and status text switch between upgrades-disabled, max-level, insufficient-materials, and ready. Clicking calls the same upgrade service as the command.

The GUI and the upgrade flow share one quote function (preview): the GUI renders costs from the state at render time, and clicking Upgrade re-quotes and charges from that result. The numbers agree while the player's state is unchanged; if the state moved in between (a material was consumed elsewhere, for example), the re-quote and actual charge win, and a shortfall fails the whole attempt without charging.

Skill sources and tag limits in config.yml ​

Both blocks below live in plugins/EmakiSkills/config.yml and control how skills are recognized and how many can be equipped.

Equipment skill source switches ​

yaml
skill_sources:
  read_lore_skills: true
  read_pdc_skills: true
  require_lore_pdc_match: false
FieldTypeRequiredDefaultValuesDescription
skill_sources.read_lore_skillsbooleanNotruetrue / falseWhether to read skills from equipment lore.
skill_sources.read_pdc_skillsbooleanNotruetrue / falseWhether to read skills from equipment PDC.
skill_sources.require_lore_pdc_matchbooleanNofalsetrue / falseStrict mode. When enabled, only the lore∩PDC intersection for the same item and slot is kept; skills present on just one side do not apply.

The config precheck warns when both sides are off, or when strict mode is on with only one side enabled.

Tag equip limits ​

When a skill's tags match an entry here, a player may equip at most that many skills carrying the tag:

yaml
skill_tags:
  equip_limits:
    ultimate: 1
    mobility: 2
FieldTypeRequiredDefaultValuesDescription
skill_tags.equip_limits.<tag>integerNonone (unlimited)> 0; <= 0 or non-integer values ignore the keyMaximum number of skills with that tag equipped at once. Tag names are id-normalized with - turned into _.
tag_limitsmapNononeSame as aboveLegacy key. Read as a fallback when skill_tags.equip_limits is empty.

So at most one ultimate skill and two mobility skills can be equipped at the same time. Tags not listed here are unlimited.
