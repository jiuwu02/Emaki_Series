EmakiDungeon ​

EmakiDungeon is a party dungeon plugin: you team up, pick a difficulty, clear a private dungeon world together, and claim the loot

  • Every party gets its own world cloned from the template, so runs never interfere with each other, and the world is deleted as soon as the run ends
  • The dungeon ships with a complete challenge flow: first pick the difficulty and drop mode, then confirm ready, wait out the world preparation countdown, and enter
  • Entry limits are managed per day / week / month, with challenge time windows, weekdays, week-of-month, and cooldown support
  • Routed rewards go into a stash first and are only paid out on clear; leaving mid-run or failing voids everything, and player state rolls back to a snapshot taken on entry
  • Built-in party system (invite / apply / kick / party channel); in-dungeon chat is isolated from global chat by default, and you can toggle global listening any time
  • Built-in map editor: mark regions, place markers, fill blocks, run a test start in game, and write back to the template on save
  • The run is described by flow.yml: rooms, waves, gates, branch options, trigger zones, timers, kill targets, and 22 module types in total
  • GraalJS dungeon scripts and CoreLib action pipelines let you hook custom logic to dungeon lifecycle events

Core capabilities ​

CapabilityDescription
Instance world poolWorlds are cloned from templates, one spare world is kept warm per dungeon (pool.max-worlds, global limit.max-instances); worlds are created on demand and deleted on dispose, and startup self-checks clean up leftovers
Challenge flowLeader starts, difficulty select, drop-mode select, full-party ready confirmation (times out to cancel), world preparation wait (bossbar or chat, cancellable), then entry counts against limits
Three-tier entry limitsDaily / weekly / monthly counts with challenge windows, evaluated in the order month > week > day, plus a standalone cooldown; counters bucket by server timezone or general.timezone
Reward stash and payoutRouted loot is stashed during the run and paid into the reward box or inventory on clear using the chosen drop mode; failing voids the stash and restores the player snapshot
Party and chat isolationParty size and invite mode are configurable; dungeon chat stays inside the instance unless the player runs /edg globalchat on, and the party channel is separate
Command guardCommands inside a dungeon pass a blacklist/whitelist filter, escape commands (like /tp *) sit in a separate blacklist that no allow-rule can override, and players crossing the boundary are pulled back
Map editorA separate edit world with two-point regions, six marker types, area fill, panel field editing, test start (no counts, no leaderboard), write-back only on save
Scoring and rankingFive weights (damage, kills, heal, deaths, defense) feed the score, plus per-dungeon leaderboards and personal stats
Lifecycle actions11 lifecycle segments (from dungeon_enter to dungeon_destroy) run through the CoreLib action pipeline for broadcasts, sounds, and custom logic
Runtime monitorsAlert thresholds for MSPT P95, heap slope, and write-queue backlog (threshold <= 0 disables), reported to console and the audit log

Default configuration layout ​

text
plugins/EmakiDungeon/
├── config.yml               ← main configuration (global switches and limits)
├── world/
│   └── <dungeonId>/
│       ├── config.yml       ← per-dungeon config (auto-generated when missing)
│       ├── flow.yml         ← flow definition (auto-generated when missing)
│       └── region/          ← dungeon map region files
├── gui/
│   └── rewardbox.yml        ← reward box GUI (pages and capacity)
├── scripts/                 ← GraalJS dungeon scripts, file name = <dungeonId>.js (optional)
├── instances.yml            ← runtime instance records (auto-generated, do not edit)
├── parties.yml              ← party snapshots (auto-generated, do not edit)
└── lang/

A dungeon template is simply a folder under world/, and the folder name is the dungeon ID. On startup and on /edg admin reload the plugin scans that directory and fills in a missing config.yml or flow.yml from the bundled templates, without overwriting existing files

Typical workflow ​

  1. First create a folder under plugins/EmakiDungeon/world/ as the dungeon ID (for example my_dungeon) and drop your map region files into it (or start empty and build with the editor)
  2. Restart the server or run /edg admin reload; the missing config.yml and flow.yml are generated for you
  3. Run /edg editor my_dungeon, place markers, wire the flow, and click "Save and write back" when done
  4. Then tune difficulty, entry limits, and drop modes in config.yml, and run /edg admin reload again
  5. Players run /edg list to see dungeons and /edg enter my_dungeon to start; the leader picks a difficulty and everyone confirms readiness
  6. On clear, open the reward box (/edg rewards), or turn the reward box off in config to send payouts straight to the inventory
