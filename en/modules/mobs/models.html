Entity Models & Animations ​

A custom mob can be attached to a 3D model, with standard actions, K-frames, and distance tiers (LOD) configured alongside. EmakiMobs can attach custom mobs to 3D models rendered by ModelEngine or BetterModel, driving standard actions, keyframe (K-frame) events, and distance-based LOD. Both model backends are optional dependencies: with neither installed, the model layer is silently disabled and mobs run in vanilla form

Prerequisites ​

  1. Install the ModelEngine (paid) or BetterModel (free, open source) plugin itself
  2. Place Blockbench-exported .bbmodel blueprints into that plugin's blueprints/ directory and wire up the resource pack containing the model textures
  3. Pick the backend in EmakiMobs' config.yml under model: (see below)
  4. Add a model: section to the mob definition YAML (see below)

Blueprint name resolution inside each backend is that backend's own business; EmakiMobs only queries by string name

Force BetterModel and tighten the mid tier to 24 blocks:

yaml
model:
  api: "better_model"
  lod:
    near: 12.0
    mid: 24.0
    far: 48.0

Mob definition model: section ​

yaml
model:
  blueprint: "bone_lord"        # required: model blueprint name
  api: "model_engine"           # optional: overrides the global model.api, selecting the backend for this mob
  scale: 1.2                    # optional: model scale, default 1.0
  animations:                   # optional: standard action → engine animation name
    idle: "breath"
    walk: "walk_slow"
    run: "run_fast"
    death: "die"
    hurt: "flinch"
    attack: "swing"
    skill: "cast"
    interact: "nod"
  keyframes:                    # optional: K-frame timelines for any animation
    attack:
      duration_ticks: 24        # timeline length in ticks
      loop: false               # whether playback loops
      priority: "action"        # ambient|utility|action|reactive|terminal
      conflict: "replace"       # replace|reject policy for equal priorities
      frames:
        - tick: 0
          action: "self | play_sound sound=minecraft:entity.wither.shoot"
        - tick: 10
          label: "impact"
          action: "self | spawn_particle particle=flame"
  lod:                          # optional: overrides the global model.lod, giving this mob its own tier bounds
    near: 12.0
    mid: 24.0
    far: 40.0

  • model.api and model.lod take effect per mob: the backend bridge is resolved and cached by the api value, and LOD tiers are decided by this mob's own bounds. Without api the mob inherits the global model.api; without lod it inherits the global model.lod

Standard actions ​

ActionTriggered byDefault priorityLoops
idleafter attach / after a transient action finishes / standing stillambientyes
walkhorizontal speed ≥ walk_speed_thresholdambientyes
runhorizontal speed ≥ run_speed_thresholdambientyes
attacklanding a hit (on_damage_give)actionno
skillskill cast (via mob_play_animation)actionno
interactinteraction (via mob_play_animation)utilityno
hurttaking damage (on_damage_take)reactiveno
deathdeath (on_death), detach follows after the delayterminalno

Priority rules: a higher tier pre-empts the current playback; equal tiers resolve by the conflict policy (replace or reject); lower-tier requests are rejected. terminal (death) cannot be pre-empted. A standard action with no timeline uses the default duration (20 ticks) plus that action's built-in priority and looping setting

Keyframes (K-frames) ​

Timelines are driven by EmakiCoreLib's animation scheduler: when playback starts, tick: 0 frames run immediately and later frames fire at their exact tick on the entity's owner thread. A frame payload is one CoreLib action pipeline line, so any registered stage (spawn_particle, play_sound, attribute changes, state switches, ...) plus the whole expression/placeholder syntax is reusable as-is

Action stages ​

Any CoreLib action line (skills, loot actions, third-party plugins) can use:

text
self | mob_play_animation animation=spin
self | mob_stop_animation animation=spin
self | mob_set_model blueprint=bone_lord_phase2
StageParameterTypeRequiredDefaultDescription
mob_play_animationanimationstringYesnoneAn action key defined in the mob's model.animations / model.keyframes; missing or blank returns a configuration error
mob_stop_animationanimationstringYesnoneAs above; stops playback of the matching definition
mob_set_modelblueprintstringYesnoneThe new blueprint name; missing or blank returns a configuration error, and a blueprint the backend cannot find logs a warning and keeps the current model
  • All three require the target to resolve to a managed mob entity; a non-managed entity returns skipped without an error
  • mob_set_model hot-swaps the blueprint (reusing the definition's scale) and falls back to idle afterwards

Third-party extensions ​

Other plugins can register animation definitions, play them, and observe playback through EmakiCoreLibApi (see CoreLib animation system). EmakiMobs consumes the same registry, so third-party mob:<id>:<key> definitions are directly referenceable by mob_play_animation
