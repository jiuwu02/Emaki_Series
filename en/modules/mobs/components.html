Components Reference ​

Fields under the components section are mapped directly to Minecraft entity attributes or data components by ComponentMapper. Key names must match the tables on this page exactly: keys with no handler are skipped silently (no error, no log line).

Shipped examples: the mobs/example_zombie.yml released on first start plus the bundled mobs/elite_zombie.yml and mobs/bone_lord.yml all use the fields below and can be read side by side with this page.

"Required" is always "No" below — the whole components section may be omitted, and a key that is not written is never applied. "Default" is always "—", meaning the vanilla or existing entity state is kept. An accepted value of "—" means the source performs no validation (numbers are written as-is and out-of-range behaviour is decided by the vanilla attribute/entity API).

Spawn versus refresh semantics ​

  • Applied on spawn only: absorption, freeze_ticks, fire_ticks, potion_effect, and every equipment field (helmet, chestplate, leggings, boots, main_hand, off_hand, equipment). These are consumable states, so the refresh triggered by /emakimobs reload never resets them and never restores broken or removed gear.
  • max_health is special: on spawn the ceiling is applied and health is filled to it; on refresh the current health is kept and clamped to the new ceiling (raising the ceiling does not heal, lowering it clamps health).
  • Every other component (attribute and appearance/behaviour fields) is written again on every refresh.

Loot fields ​

FieldTypeRequiredDefaultAccepted valuesDescription
loot_tablestringNo—<namespace>:<path> or a bare path (auto-prefixed with minecraft:)Two jobs in one key: the value is handed to Bukkit.getLootTable to look up a vanilla/datapack loot table (the plugin registers no datapack, so a custom namespace usually resolves to nothing and becomes a silent no-op), while the key's presence is the on/off switch for loot_tables/<mob_id>.yml.
can_pick_up_lootbooleanNo—true / falseWhether the mob can pick up items from the ground.
remove_when_farbooleanNo—true / falseDespawn when players move away (overrides persistent).

loot_table behaves contrary to intuition

  • Only when the loot_table key is present is loot_tables/<mob_id>.yml read and applied on death; and as soon as that YAML table exists, death runs event.getDrops().clear(), wiping all vanilla drops (kill experience is still kept via experience).
  • To keep vanilla drops, do not write a loot_table key — at the cost of the same-named YAML loot table never applying.
  • Writing a vanilla key such as loot_table: "minecraft:entities/zombie" additionally sets a vanilla loot table, yet with a matching YAML table present the vanilla drops are still cleared. The bundled examples use emakimobs:entities/<mob_id>, which resolves to no table and only acts as the switch.

ItemConfig fields:

FieldTypeRequiredDefaultAccepted valuesDescription
itemstringNo—a vanilla material name (case-insensitive, optional minecraft: prefix)Only materials that are items are accepted; when matching fails the slot is left as-is.
drop_chancedoubleNo— (vanilla default drop chance)0.0–1.0Drop probability on death; 0.0 means never drops. Not clamped locally — out-of-range values are decided by the vanilla equipment API.
yaml
components:
  main_hand:
    item: "minecraft:iron_sword"
    drop_chance: 0.05
  helmet:
    item: "minecraft:iron_helmet"
    drop_chance: 0.0
  equipment:
    legs:
      item: "minecraft:iron_leggings"
      drop_chance: 0.0
    # A bare material name works when only the item matters
    feet: "minecraft:iron_boots"

Potion effect field ​

FieldTypeRequiredDefaultAccepted valuesDescription
potion_effectstring or string listNo—colon-separated effect strings, see belowPotion effects applied on spawn (applied on spawn only). Use a single string for one effect or a list for several.

Each effect is one colon-separated string:

text
<effect type>:<duration ticks>[:<amplifier>]
SegmentRequiredDescription
Effect typeYesVanilla effect ID, case-insensitive (speed, regeneration, fire_resistance, …), looked up in the minecraft: namespace.
Duration ticksYesDuration in ticks; must parse as an integer.
AmplifierNoDefaults to 0 (level I); 1 is level II.
yaml
components:
  potion_effect:
    - "speed:99999:1"
    - "regeneration:600"
  # A single effect can be written as a plain string
  # potion_effect: "fire_resistance:1200"

The mapping form is not supported

potion_effect parses only the colon-separated string above. Writing - type: SPEED with duration: and amplifier: keys raises no error, but the whole effect is discarded. ambient, particles and icon are not configurable. An unknown effect type, a missing duration, or an unparsable number also skips the entry silently.
