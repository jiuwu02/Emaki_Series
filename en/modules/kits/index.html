EmakiKits ​

EmakiKits is a configuration-driven kit plugin. Join, invite, daily, weekly, monthly, CDK, choice, and generic kits are all defined in YAML, and kit types differ only in configuration

  • Kit definitions live under plugins/EmakiKits/kits/: one kit per YAML file, and the kit id comes from the id field inside the file, not the file name
  • Reward items reference CoreLib item-source shorthands (minecraft-bread, emakiitem-flame_blade, and so on) instead of hand-building materials and lore inside the kit
  • There are four reward types: item, money, nested_kit (reference another kit), and action (a CoreLib action pipeline line)
  • Each option of a choice kit is a "mini kit" (several rewards); max_select: 1 means the player picks exactly one. Every kit inlines its own GUI layout in the choice.gui section
  • Supports fixed rewards, weighted random rewards, paid purchases, cumulative open milestones, time windows (always / range / cron), nested child kits, and cycle detection
  • Claiming, redeeming, and buying all go through idempotency keys and audit records that survive a restart

Kit types ​

typeTrigger
joinA new player's first join; an existing player's invite code (UUID or name) must be entered within the play-time window
inviteGranted after an invite relationship is bound, according to reward_target
daily / weekly / monthlyOne claim per period key derived from cycle.timezone
cdkRedeemed with /emakikits redeem; global-once or per-player-once
choiceOpens the inlined GUI to pick one mini kit; max_select controls how many options can be chosen
genericManually claimed, optionally combined with purchases, open milestones, and time windows

Configuration layout ​

text
plugins/EmakiKits/
├── config.yml                  # Main config (version, language, storage, economy, invite, CDK, nesting, join window)
├── kits/
│   ├── join_welcome.yml        # One kit per file; id comes from the id field inside
│   ├── invite_reward.yml
│   ├── daily_login.yml
│   ├── weekly_supply.yml
│   ├── monthly_crate.yml
│   ├── cdk_global.yml
│   ├── cdk_per_player.yml
│   ├── choice_starter.yml      # Includes an inlined choice.gui layout
│   ├── generic_crate.yml
│   └── nested_child.yml        # Referenced by other kits
├── gui/                        # Optional external GUI templates (choice.gui_template fallback)
├── data/                       # Runtime save (audit, idempotency keys, counters)
└── lang/
    ├── zh_CN.yml
    └── en_US.yml

With release_default_data: true the ten bundled example kits are released on first start; existing files are never overwritten

Dependencies and integrations ​

ModuleRelationship
EmakiCoreLibRequired: item sources, createConfiguredItem, the action pipeline, GUI service, template loader, economy bridge, cron, and message service
EmakiItemOptional: grant its custom items via the emakiitem-<itemId> shorthand
Vault / ExcellentEconomyOptional: money rewards and purchase debits go through the CoreLib economy bridge; a paid purchase is rejected when no bridge is installed

Getting started ​

  1. Install EmakiCoreLib and EmakiKits, start once, and confirm the example kits were released under plugins/EmakiKits/kits/
  2. Copy a kits/*.yml, change id, type, and rewards, then run /emakikits reload
  3. Run /emakikits list to confirm the kit loaded, and /emakikits claim <kitId> to verify it
  4. For a choice kit use /emakikits choose <kitId> to open the inlined GUI; appending option ids skips the GUI
