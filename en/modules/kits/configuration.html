Configuration and kit definitions ​

EmakiKits has two configuration layers: plugins/EmakiKits/config.yml holds global switches, and plugins/EmakiKits/kits/*.yml holds kit definitions, one kit per file

config.yml ​

KeyTypeDefaultPurpose
versionstring1.0.1Resource version, maintained by the module version sync flow
languagestringzh_CNUse lang/<language>.yml
release_default_databooleantrueWhether to release the bundled example kits and lang on first start
timezonestringAsia/ShanghaiUsed by daily/weekly/monthly kits that do not set cycle.timezone
join.missed_window_secondslong7200Play-time window (seconds) for a new player to enter an invite code; missed kits are not granted later
join.invite_code_typestringuuidInvite code type: uuid or name
storage.backendstringyamlSave backend, currently yaml only
storage.save_delay_ticksint20Dirty-data flush interval (ticks)
storage.atomic_writesbooleantrueUse tmp + move atomic replacement

economy.currency_idstring""ExcellentEconomy currency id; leave empty for Vault

invite.require_new_playerbooleantrueWhether the invitee must be a first-join player
invite.allow_mutualbooleanfalseAllow mutual invite chains
invite.max_binds_per_inviteeint1Maximum binds per invitee

Top-level fields of kits/*.yml ​

FieldRequiredPurpose
idyesUnique kit id: lowercase letters, digits, underscores, and hyphens; independent of the file name
typeyesjoin / invite / daily / weekly / monthly / cdk / choice / generic
enabledno (default true)Whether the kit is enabled
display_nameno (default id)Player-facing name
permissionno (default emakikits.claim)Permission required to claim; must start with emakikits.
max_claims_totalno (default 0)Total claim limit, 0 for unlimited
join / invite / cycle / cdk / choice / purchase / open / limit / rewardsnoUsed by type and feature, see below

At load time the plugin validates id syntax, duplicate ids, unknown types, permission prefixes, time zones, CDK codes, choice counts, purchase limits, open milestones, reward fields, limit modes, and nested-kit self-references / cycles / missing targets / depth. Kit files with problems are skipped with a warning

The four reward types ​

rewards.fixed is always granted. rewards.random rolls one weighted entry when rewards.weighted: true, otherwise all entries are granted. choice.options.<option>.rewards and open.milestones.<count>.rewards use the same entry format

typeFieldsPurpose
itemsource (required), amountsource is a CoreLib item-source shorthand (minecraft-bread, emakiitem-flame_blade, itemsadder-xxx). The item is built with EmakiCoreLibApi.createConfiguredItem and added to the inventory; overflow drops at the player's feet
moneyamountAdd money through the CoreLib economy bridge
nested_kitkit_id (required)Expand the rewards of another kits/*.yml kit, bounded by nested.max_depth
actionaction (required)One complete CoreLib action pipeline line, run with executeActionLineAsync with the claiming player as caster; omitting a source defaults to self

Common fields: id (entry id), permission (optional, the entry is skipped when the player lacks it), weight (weighted random only)

NOTE

action rewards run asynchronously: the claim's idempotency key is written before the action is submitted, and a failed action records an audit entry and a WARNING log but does not roll back the whole claim. Available variables: %var.kit%, %var.player%, %var.uuid%, %var.amount%

yaml
rewards:
  weighted: true
  fixed:
    - type: "item"
      id: "welcome_bread"
      source: "minecraft-bread"
      amount: 8
    - type: "action"
      id: "welcome_msg"
      action: 'send_message text="<green>Welcome to the server!</green>"'
  random:
    - type: "money"
      id: "roll_money"
      amount: 200
      weight: 5
    - type: "nested_kit"
      id: "roll_nested"
      kit_id: "nested_child"
      weight: 1

Choice kits and inline GUI ​

Each option of a choice kit is a "mini kit": rewards can hold several entries, or kit_id can reference another kit file. min_select / max_select control the option count; max_select: 1 means exactly one

Every kit inlines its own GUI layout in choice.gui (parsed by CoreLib GuiTemplateParser): gui_type, title, rows, slots. Slot keys with type: "choice_option" must match choice.options keys, and the confirm slot submits the selection. Alternatively, choice.gui_template can point to an external template id under gui/

yaml
choice:
  min_select: 1
  max_select: 1
  gui:
    id: "choice_starter_gui"
    gui_type: CHEST
    title: "<dark_gray>Newbie pick - <gold>%kit%</gold></dark_gray>"
    rows: 3
    slots:
      sword:
        type: "choice_option"
        slots: [10]
        item:
          source: "minecraft-iron_sword"
          components:
            custom_name: "<aqua>Warrior mini kit</aqua>"
      confirm:
        type: "confirm"
        slots: [22]
        item:
          source: "minecraft-emerald_block"
  options:
    sword:
      display: "Warrior mini kit"
      rewards:
        - type: "item"
          source: "minecraft-iron_sword"
          amount: 1
        - type: "item"
          source: "minecraft-bread"
          amount: 4
        - type: "action"
          action: 'heal amount=2'

Time windows (limit) ​

Only active when enabled: true; mode is one of:

modeFieldsPurpose
always—No limit
rangestart, endClosed ISO-8601 timestamp interval
croncron (6 fields), duration_seconds, timezoneCoreLib cron expression; each fire opens a window for duration_seconds seconds

Purchases and open milestones ​

  • purchase: enabled, price, economy_provider, currency_id, max_purchases (0 = unlimited), count_pass_to_nested. A purchase with price > 0 is rejected when the economy bridge is unavailable
  • open: enabled, max_opens (0 = unlimited), milestones.<count>.rewards grants extra rewards when the cumulative open count reaches that number
