Configuration Directory ​

EmakiAttribute configuration consists of the main config, attribute definitions, damage types, conditions, lore formats, and attribute balance data. Define a stable attribute naming convention before expanding damage types and equipment sources.

Default directory structure ​

text
plugins/EmakiAttribute/
├── config.yml
├── attribute_balance.yml
├── attributes/
├── damage_types/
├── conditions/
├── lore_formats/
├── presets/
├── gui/
├── lang/
└── data/
PathPurpose
config.ymlMain config: default resources, damage interception, regeneration, scaling curves, and vanilla damage mappings.
attribute_balance.ymlAttribute score and balance semantics parameters.
attributes/Individual attribute definitions.
damage_types/Damage pipelines, such as physical, projectile, and spell.
conditions/Attribute read conditions (PDC read rules).
lore_formats/Attribute display format templates.
presets/Attribute preset definitions.
gui/Attribute points GUI configuration (attribute_points.yml).
lang/Language files; bundled zh_CN.yml and en_US.yml.
data/Runtime data, for example data/parent_attributes/<UUID>.yml; usually not edited manually.

Suggested edit order ​

  1. Define attribute ids, display names, value kinds, and caps in attributes/.
  2. Define how legacy lore is read or displayed in lore_formats/.
  3. Configure damage stages in damage_types/.
  4. Write attributes from equipment, gems, strengthening, forging, or item modules.
  5. Run /ea lint, then /ea reload and /ea resync <player> after every change.

Main config fields ​

The table below covers every top-level key in config.yml. The nested sections (default_profile, shield, synthetic_hit_feedback, damage_indicator, scaling_curves, allowed_damage_causes) are listed under their own sections.

Bundled defaults (top-level keys only; the full contents of default_profile, shield, synthetic_hit_feedback, damage_indicator, and allowed_damage_causes are in their own sections):

language: "zh_CN"
release_default_data: true
attribute_sources:
  read_lore_attributes: true
  read_pdc_attributes: true
  require_lore_pdc_match: false
hard_lock_damage: true
default_damage_type: physical
projectile_damage_type: projectile
vanilla_event_damage:
  enabled: true
  damage_type: physical
same_signature_ignores_invulnerability:
  enabled: true
  window_ms: 500
attack_speed:
  scope: global
regen_interval_ticks: 20
sync_delay_ticks: 1
health_display_scaling:
  enabled: false
  target: 20.0
default_profile:        # see "Default resources and attributes"
shield:                 # see "Shield blocking"
synthetic_hit_feedback: # see "Synthetic hit feedback"
damage_indicator:       # see "Damage indicators"
scaling_curves: {}      # empty map by default, so no decay applies
allowed_damage_causes:  # see "Vanilla damage mapping"; 33 cause mappings ship by default

Example: read item attributes from PDC only, and keep perfect takeover.

yaml
attribute_sources:
  read_lore_attributes: false
  read_pdc_attributes: true
vanilla_event_damage:
  enabled: true
  damage_type: physical

Item attribute source policy ​

attribute_sources controls whether item attributes are read from Lore, PDC, or both, and whether both sources must validate each other:

yaml
attribute_sources:
  read_lore_attributes: true
  read_pdc_attributes: true
  require_lore_pdc_match: false

The default preserves the legacy behavior: all enabled Lore and PDC sources contribute to the item snapshot. When require_lore_pdc_match is enabled, values are compared per attribute ID:

  • Present in both sources with equal values: count the attribute once.
  • Present in both sources with different values: reject the attribute.
  • Present in only one source: reject the attribute.
  • Fixed and spread/range values use the same matching rule.

Match mode requires both read switches. Precheck emits a warning when either source is disabled. If both sources are disabled, default, temporary, and other entity-level sources remain available, but equipped items contribute no Lore/PDC attributes.

Default resources and attributes ​

default_profile defines the resources and attribute baselines a player has on initialization:

yaml
default_profile:
  resources:
    health:
      display_name: "生命值"
      default_max: 20.0
      min_max: 1.0
      max_max: 2048.0
      sync_to_bukkit: true
      full_on_init: true
    mana:
      display_name: "法力值"
      default_max: 100.0
      min_max: 0.0
      max_max: 99999.0
      sync_to_bukkit: false
      full_on_init: true
  attributes:
    physical_attack: 0.0
    physical_defense: 0.0
    health_regen: 0.1
    mana_regen: 0.1

default_profile.resources.<id> ​

default_profile also recognizes the optional section-level keys id (default default), priority (default 1000000), and description (default empty); the bundled config.yml does not write them.

default_profile.attributes.<attribute_id> ​

FieldTypeRequiredDefaultRangeDescription
<attribute id>doubleNo0finite number (invalid falls back to 0)Baseline injected for that attribute on initialization; attributes not listed receive no default.

Bundled default resources:

  • health: default max 20, synced to Bukkit, min max 1, max max 2048.
  • mana: default max 100, not synced to Bukkit, min max 0, max max 99999.

Resources cover changeable pools such as health and mana; attributes are used by equipment, gems, strengthening, skills, and damage calculation. A resource with sync_to_bukkit: true is mirrored to its Bukkit counterpart, which is typically used for health.

yaml
# Add a rage resource that regenerates 5 points per second
default_profile:
  resources:
    rage:
      display_name: "Rage"
      default_max: 100.0
      min_max: 0.0
      max_max: 100.0
      sync_to_bukkit: false
      full_on_init: false
      regen_per_second: 5.0

Shield blocking ​

shield decides whether the block is resolved by vanilla or by EA. See "Shield blocking" in Damage System.

yaml
shield:
  mode: vanilla
  require_facing: true
  facing_angle_degrees: 180
FieldTypeRequiredDefaultRangeDescription
modestringNovanillavanilla / attributevanilla keeps the vanilla BLOCKING; attribute zeroes it and resolves the block in the damage type's block stage. Any other value is treated as vanilla.
require_facingbooleanNotruetrue / falseOnly applies in attribute mode: whether the source must be in front of the target. Environmental damage has no source direction and never counts as a frontal block.
facing_angle_degreesdoubleNo1800 – 180 (clamped into range)Facing check angle in degrees; 180 is the half-plane centered on the view direction.

Example: switch to percentage blocking.

yaml
shield:
  mode: attribute
  require_facing: true
  facing_angle_degrees: 180
# then lower default_profile.attributes.block_reduction (for example to 40) to get 40% mitigation

Synthetic hit feedback ​

synthetic_hit_feedback only re-applies knockback and hurt sound in compatibility mode (vanilla_event_damage.enabled: false).

yaml
synthetic_hit_feedback:
  knockback: true
  knockback_strength: 0.4
  hurt_sound: true
FieldTypeRequiredDefaultRangeDescription
knockbackbooleanNotruetrue / falseWhether to add knockback feedback.
knockback_strengthdoubleNo0.4≥ 0 (negative is treated as 0)Knockback strength; higher values move the target further.
hurt_soundbooleanNotruetrue / falseWhether to play hurt sound feedback.

Example: disable synthetic knockback when a custom knockback plugin is present.

yaml
synthetic_hit_feedback:
  knockback: false
  hurt_sound: true

Damage indicators ​

damage_indicator controls the floating damage numbers. The render backend comes from EmakiCoreLib's display.backend: with the packet backend only the players selected by visible_to can see them; with the bukkit backend the indicator is a real entity visible to every nearby player and visible_to has no effect.

yaml
damage_indicator:
  enabled: true
  merge_window_ms: 500
  max_per_target_per_second: 4
  visible_to: "involved"
  ignored_causes:
    - FIRE_TICK
    - POISON
    - WITHER
    - DROWNING
    - FREEZE
    - SUFFOCATION
    - STARVATION
  lifetime_ticks: 24
  spawn:
    offset:
      x: 0.0
      y: 2.0
      z: 0.0
    random_offset:
      x: 0.4
      y: 0.15
      z: 0.4
  motion:
    enabled: true
    step_ticks: 2
    speed: 0.30
    gravity: -0.030
    direction:
      mode: "random"
      fixed:
        x: 0.0
        y: 1.0
        z: 0.0
      pitch:
        min: 55.0
        max: 85.0
      yaw:
        min: -180.0
        max: 180.0
    scale:
      pop_from: 0.6
      pop_ticks: 3
      shrink_to: 0.0
      shrink_ticks: 6
  triggers:
    normal:
      enabled: true
    critical:
      enabled: true
    heal:
      enabled: true
    dodge:
      enabled: true

Example: a faster critical indicator plus spam suppression.

yaml
damage_indicator:
  enabled: true
  max_per_target_per_second: 2
  triggers:
    critical:
      enabled: true
      motion:
        speed: 0.42
        gravity: -0.036
        scale:
          pop_from: 0.35
          pop_ticks: 4

Vanilla damage mapping ​

allowed_damage_causes decides which Bukkit DamageCause values enter attribute resolution:

yaml
allowed_damage_causes:
  - cause: FALL
    damage_type: physical
    enabled: true
  - cause: LAVA
    damage_type: physical
    enabled: true
FieldTypeRequiredDefaultRangeDescription
causestringYes—Bukkit EntityDamageEvent.DamageCause nameVanilla cause to map; an entry without it is ignored.
damage_typestringNodefault_damage_type—Damage type id from damage_types/*.yml; /ea lint reports it when unloaded.
damagedoubleNothe vanilla event damage when omitted≥ 0 (negative is treated as 0)Base damage before the attribute pipeline. When omitted, the vanilla value already computed by the server is used, which suits fall, explosion, burning, drowning, and other height- or state-dependent sources.
enabledbooleanNotruetrue / falseWhether this mapping is active; false means it never matches.
context.<key> (or any other key)anyNo——Injected into this hit's damage context for stage expressions and message templates. cause, damage_type, damage, enabled, and context are reserved; every other key becomes a context variable.

Example: route fall damage through the physical pipeline using the vanilla value, and pin lava damage to a fixed base.

yaml
allowed_damage_causes:
  - cause: FALL
    damage_type: physical
    enabled: true          # no damage, so the vanilla fall damage is used
  - cause: LAVA
    damage_type: spell
    damage: 8              # override with a fixed base of 8
    enabled: true

Unmapped vanilla damage is governed by vanilla_event_damage, not by hard_lock_damage: when enabled: true it enters the attribute pipeline as vanilla_event_damage.damage_type; when enabled: false only the causes allowed in this table enter EA and everything else keeps vanilla behavior.

Scaling curves ​

scaling_curves configures diminishing returns above a threshold and is an empty map by default (no decay):

yaml
scaling_curves:
  physical_attack_cap:
    attribute: "physical_attack"
    threshold: 500
    curve_type: "logarithmic"
    factor: 100
FieldTypeRequiredDefaultRangeDescription
<rule id> (section key)objectNo——Rule id; when attribute is omitted the key itself is used as the attribute id.
attributestringNosection key—Attribute id affected by this rule; a rule pointing at an unknown attribute has no effect.
thresholdnumberNo0≥ 0 (negative is treated as 0)Value where diminishing returns begin; at or below it the value is unchanged.
curve_typestringNologarithmiclogarithmic / sqrt / piecewise_linear (alias linear)Curve function; unrecognized values fall back to logarithmic and are reported by the config precheck.
factornumberNo1logarithmic / sqrt: > 0 (≤ 0 is treated as 1); piecewise_linear / linear: ≥ 0Curve factor: a divisor for the first two, a retention ratio for the last, where 0 is valid and drops the whole excess.

Full curve semantics and tuning advice are in Scaling Curves.

Troubleshooting ​

  • Attribute not displayed: check that the attribute file loaded, that the lore format matches, and that equipping the item triggered a refresh.
  • Attribute has no effect: check that the attribute ID matches the damage type, condition, or external module.
  • Unexpected environmental damage: check vanilla_event_damage and allowed_damage_causes (hard_lock_damage has no runtime effect and does not need investigating).
  • Health out of sync: check that the resource declares sync_to_bukkit: true. The health resource ceiling uses the modified MAX_HEALTH: the EA-computed value is written to the base, and max_health_vanilla, health-boost potions, and third-party plugin modifiers stack on top without conflicting with each other. If the cap differs from expectations, enable the resource debug channel and inspect the health-cap resolution and max-health modifier lines to locate each modifier source.
  • External healing reverted: the health current value follows the player entity's health, so another plugin or command setting health directly is not wiped by the next sync. If values still fall back, enable the resource debug channel and compare the old current value with the engine baseline value on the natural regeneration line: a persistent gap means the resource is not synced to Bukkit, or health is being rewritten by another plugin within the same tick.
  • Value inflation: configure scaling_curves for core damage, defense, and critical attributes.
