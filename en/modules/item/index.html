EmakiItem ​

EmakiItem provides lightweight custom items, stable item IDs, sets, trigger actions, auto update, and PlaceholderAPI support. It is often the starting point for equipment progression.

Stable item IDUses config IDs instead of display names.

Skill bindingCan expose skills or skill unlock data.

Default runtime folder ​

text
plugins/EmakiItem/
├── config.yml
├── id_aliases.yml
├── items/
├── sets/
├── gui/
└── lang/

items/ defines items, sets/ defines item sets, gui/ holds the repair and two browser templates (repair_gui.yml, pack_browser_gui.yml, item_browser_gui.yml), and id_aliases.yml stores renamed item ID mappings.

Every subdirectory of items/ is an item pack and may carry a pack.yml defining its icon in the browser; see Browser GUI.

Main configuration ​

config.yml contains only global settings; item behavior lives in the individual definition files. "Required" reflects whether the source has a fallback: every key below has one, so all are "No". "Range" states the real constraint in the source; "—" means the source performs no validation.

Top-level settings ​

FieldTypeRequiredDefaultRangeDescription
versionstringNo"2.8.1"—Config structure marker maintained by the project's resource sync flow, not a feature switch. Falls back to 2.6.7 when absent.
languagestringNozh_CN—Language file name, matching lang/<language>.yml. Falls back to zh_CN when absent.
release_default_databooleanNotruetrue / falseWhether bundled default data such as items/ and sets/ is released at startup; when disabled only existing data is loaded and no missing sample is generated. This does not control config.yml or language files.
yaml
# Shipped defaults
version: "2.8.1"
language: "zh_CN"
release_default_data: true

Usage example: switch to English and stop releasing sample data.

yaml
language: "en_US"
release_default_data: false

data_directories ​

FieldTypeRequiredDefaultRangeDescription
data_directoriesobjectNo——Directory scan settings, applied to items/ and sets/.
data_directories.max_depthintNo2>= 1 (the source applies max(1, value))Maximum recursive subdirectory depth, counting the data directory itself: 1 reads only .yml files at the directory root, 2 allows one level of subdirectories, 3 allows two. Directories beyond the limit are skipped with a warning.
yaml
# Shipped defaults
data_directories:
  max_depth: 2

Usage example: allow two levels of subdirectories (for example items/<pack>/<subdir>/*.yml).

yaml
data_directories:
  max_depth: 3

# Shipped defaults
set_bonus:

    held_change: true

yaml
set_bonus:

    inventory_drag: false

item_state ​

FieldTypeRequiredDefaultRangeDescription
item_stateobjectNo——Custom item-state settings written to the emaki:item_state PDC and read/written by the item_state_* action stages and the API. The whole section is additive: leaving it untouched keeps the previous behavior.
item_state.clampbooleanNotruetrue / falseWhether written values are clamped to the min/max declared in fields. When disabled only overflow protection remains, with no configurable clamping.
item_state.fill_defaultsbooleanNotruetrue / falseWhether add uses the fields default as the starting value when the field is absent. When disabled a missing field is rejected outright (reason=missing_state).
item_state.fieldsmapNo{}—Field declarations keyed by state key name (lowercased on write). Undeclared fields are unaffected by clamping, defaults, and thresholds.
item_state.migrationsmapNo{}—Migration steps per schema version; an empty map means no migration.
item_state.preservationobjectNo——State preservation policy.
item_state.derivationobjectNo——State-change-driven derived refreshes.

item_state.fields ​

FieldTypeRequiredDefaultRangeDescription
item_state.fields.<key>objectNo——One field declaration; <key> is the state key name.
item_state.fields.<key>.typestringNodoubleINTEGER / LONG / DOUBLE / BOOLEAN / STRING (case-insensitive)Field type. A blank or unrecognized type skips the whole field; min/max/thresholds only apply to numeric types (INTEGER, LONG, DOUBLE).
item_state.fields.<key>.defaultscalarNononeMust coerce to typeUsed as the starting value for add when the field is absent and fill_defaults is on. A value that cannot coerce means no default.

item_state.fields.<key>.thresholdsmapNo{}—Threshold set keyed by threshold id. At most the 64 smallest thresholds by ascending value are kept per field, regardless of write order; changing the set re-arms that field's once latch.

  clamp: true
  fill_defaults: true
  preservation:
    verify_rebuild: true
    repair_on_pickup: false
    repair_on_drop: false
    repair_on_trade: false
    repair_on_container_transfer: false
    repair_on_join: false
  derivation:
    enabled: false
    refresh_lore: true
    refresh_attributes: true
    scan_holder: true
    max_depth: 2

Usage example: declare a kill counter with thresholds and migrate a legacy field by schema version.

yaml
item_state:
  fields:
    kills:
      type: INTEGER
      default: 0
      min: 0
      max: 9999
      thresholds:
        novice:
          value: 10
          once: true
          message_key: "state.kills.novice"
          sound: "minecraft:entity.player.levelup"
          sound_volume: 1.0
          sound_pitch: 1.2
        veteran:
          value: 100
          actions:
            - 'send_message text="<gold>Kill streak reached.</gold>"'
  migrations:
    "1":
      from: 0
      to: 1
      rename:
        kill_count: kills
      retype:
        kills: LONG
      drop:
        - legacy_tag

proficiency_guard ​

FieldTypeRequiredDefaultRangeDescription
proficiency_guardobjectNo——Proficiency dispatch guard applied to damage_dealt / kill_entity / kill_player slot dispatch. Everything except dedupe_per_event defaults to disabled or unlimited, so existing gain rates are unchanged.
proficiency_guard.dedupe_per_eventbooleanNotruetrue / falseDispatch one item definition at most once per event, fixing "the same definition sitting in several slots fires once per slot".
proficiency_guard.max_dispatches_per_eventintNo0>= 0 (the source applies max(0, value)); 0 means unlimitedMaximum dispatches per event.
proficiency_guard.same_target_cooldown_secondsnumberNo0>= 0 (converted to milliseconds internally); 0 means no cooldownCooldown in seconds against the same target.
proficiency_guard.daily_soft_capintNo0>= 0 (the source applies max(0, value)); 0 means no capDaily soft cap. Counts live in memory, reset on the server's local date change, and do not survive a restart.
proficiency_guard.decay_factordoubleNo1.0(0, 1]; out-of-range or non-finite values fall back to 1.0Decay factor once the soft cap is exceeded. 1.0 means no decay (reject outright past the cap).
proficiency_guard.decay_minimum_ratiodoubleNo0.0[0, 1] (clamped by the source)Lower bound for the decayed pass probability.
proficiency_guard.guarded_triggerslistNodamage_dealt, kill_entity, kill_player—Triggers governed by this section; an empty list falls back to the three defaults.
yaml
# Shipped defaults
proficiency_guard:
  dedupe_per_event: true
  max_dispatches_per_event: 0
  same_target_cooldown_seconds: 0
  daily_soft_cap: 0
  decay_factor: 1.0
  decay_minimum_ratio: 0.0
  guarded_triggers:
    - "damage_dealt"
    - "kill_entity"
    - "kill_player"

Usage example: cap dispatches per event and add a 1-second cooldown against the same target.

yaml
proficiency_guard:
  max_dispatches_per_event: 3
  same_target_cooldown_seconds: 1

Interactions ​

set_bonus.refresh_triggers controls set state refreshing, while item auto-update is controlled separately by update.triggers in an item definition; neither overrides the other.

item_state.* applies to the emaki:item_state PDC partition and is read and written by the item_state_* action stages and the API. The whole section is additive: leaving it untouched keeps the previous behavior. proficiency_guard.* applies to slot dispatch for damage_dealt, kill_entity, and kill_player; everything except dedupe_per_event defaults to disabled or unlimited.

Typical item lifecycle ​

  1. Define item IDs, material, name, lore, and components in items/.
  2. Optionally add Attribute stats, Skills, or set info.
  3. An administrator gives out the item.
  4. A player uses the item.
  5. Item automatically refreshes its state when triggered.
  6. Forge / Strengthen / Gem can continue writing their own layers on top.
  7. CoreLib rebuilds the final presentation.
