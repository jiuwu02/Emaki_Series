EmakiForge ​

EmakiForge runs the whole forging flow: you place the target equipment, blueprint, and materials; it checks the recipe, capacity, and conditions, then modifies the target item or creates a new result. Quality, material contribution, and result presentation are all configured here

Shipped defaults (the config.yml published with the module; repeated quality.tiers entries are abbreviated):

yaml
version: "5.0.0"
language: "zh_CN"
release_default_data: true
quality:
  tiers:
    - name: "平庸"
      weight: 60
      multiplier: 1.0
    - name: "完美"
      weight: 1
      multiplier: 1.2
  default_tier: "平庸"
  guarantee:
    enabled: true
    threshold: 60
    minimum: "无暇"
  item_meta:
    enabled: true
    tiers:
      无暇:
        name_actions:
          - action: "prepend_prefix"
            value: "<color:#4B64C8>[无暇] </color>"
        lore_actions:
        action:
          - 'broadcast_message text="..."'
      # the other 5 tiers share this structure, see quality.md
number_format:
  default: "0.##"
  integer: "0"
  percentage: "0.##%"
op_bypass: false
condition:
  invalid_as_failure: true
history:
  enabled: true
  auto_save: true
  save_interval: 6000

Typical forging flow ​

  1. Open the forge GUI with /ef forge
  2. Place a blueprint in the blueprint slots; Forge matches the recipe by blueprint item source
  3. Place materials in the required and optional material slots
  4. Check recipe, condition, capacity, and material count
  5. Click the confirm slot to run actions.pre
  6. Resolve deterministic quality and pity from the player, recipe, and material fingerprint (the fingerprint is an identifier derived from the exact mix of materials inserted)
  7. Create the primary item from result.success.outputs and attach the forge layer snapshot
  8. Run result.success.actions → actions.success → quality actions; on failure run actions.failure
  9. The CoreLib item assembly service rebuilds the item presentation
  10. With EmakiAttribute installed, ea_attribute material effects are written to the structured PDC attribute layer (PDC, the key-value data container stored on the item)

Relation with Attribute ​

Forge can run basic forging without Attribute. The ea_attribute material effect requires EmakiAttribute: attributes are then written into a structured PDC layer, so the numbers participate in real combat calculation instead of only appearing in lore

When EmakiAttribute is absent, this effect takes a no-op path: forging still completes, it simply does not write attribute data, no error is raised, and the flow is not interrupted
