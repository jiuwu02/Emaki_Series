Configuration ​

The main configuration is plugins/EmakiStructure/config.yml; changes apply with /ems reload. Unknown top-level keys are reported as WARN by the config precheck (config.yml.<key>), and an illegal value is reported as error.config.invalid and replaced with a legal one

The shipped defaults live in EmakiStructure/src/main/resources/config.yml; version is 1.0.4 and maintained by resource sync — do not edit it

replace_rules ​

Applies only to not-yet-generated chunks. Rules are evaluated in order, and the first match wins and short-circuits; a miss lets the vanilla structure generate normally. Already-generated chunks and their structures are never rewritten

yaml
replace_rules:
  - structure: "minecraft:village_plains"   # only matches the minecraft: namespace
    template: "village_hub_a"               # replacement template (same name in structures/)
    chance: 0.5                             # probability [0.0, 1.0]
    worlds: ["world"]                       # world whitelist; absent/empty = all worlds
    biomes: ["plains"]                      # biome whitelist; absent/empty = no biome limit
    enabled: true                           # false = this rule does not participate
    apply_to_existing: false                # always false; a true value rejects the rule with a warning
  • A marker is written to replaced/<world>.marker for idempotency; replaced chunks are not replaced again
  • A missing referenced template logs a warning and lets the vanilla structure generate (console.replace_template_missing)
  • Known limitation: multi-piece structures (villages, etc.) may leave partial vanilla tail pieces
