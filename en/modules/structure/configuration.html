Configuration ​

The main configuration is plugins/EmakiStructure/config.yml; after you edit it, run /ems reload to apply the changes. If you write a top-level key the plugin does not know, the config precheck logs a WARN (config.yml.<key>); an illegal value is reported as error.config.invalid and replaced with a legal one so the plugin keeps running

The shipped defaults live in EmakiStructure/src/main/resources/config.yml; version is 1.0.8 and maintained by resource sync — do not edit it by hand

replace_rules ​

The replace_rules set applies only to not-yet-generated chunks. The plugin checks rules in order and the first match wins and short-circuits; a miss lets the vanilla structure generate normally. Already-generated chunks and their structures are never rewritten

yaml
replace_rules:
  - structure: "minecraft:village_plains"   # only matches the minecraft: namespace
    template: "village_hub_a"               # replacement template (same name in structures/)
    chance: 0.5                             # probability [0.0, 1.0]
    worlds: ["world"]                       # world whitelist; absent/empty = all worlds
    biomes: ["plains"]                      # biome whitelist; absent/empty = no biome limit
    enabled: true                           # false = this rule does not participate
    apply_to_existing: false                # always false; a true value rejects the rule with a warning
  • A marker is written to replaced/<world>.marker for idempotency; replaced chunks are not replaced again
  • A missing referenced template logs a warning and lets the vanilla structure generate (console.replace_template_missing)
  • Known limitation: multi-piece structures (villages, etc.) may leave partial vanilla tail pieces

Recognized top-level keys ​

The precheck accepts 12 top-level keys: version, language, generate, cache, selection, template, spawn, detection, cooldown, replace_rules, rollback, furniture; any other top-level key is unknown to it
