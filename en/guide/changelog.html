Changelog Notes ​

This page explains the current documentation sync focus and provides an upgrade checklist. For complete release information, also check the per-module CHANGELOG.md files, default configuration files, and the release package you are using. 13 of the 14 runtime modules ship a CHANGELOG.md; EmakiMobs does not have one yet, so use its default config.yml and release notes for version changes instead.

Legacy configured-item automatic migration has been retired ​

  • The runtime no longer migrates legacy item fields automatically: CoreLib shared GUI files and EmakiItem items/ definitions should use the canonical item.source, item.amount, and item.components directly.
  • Historical fields such as material, display_name, lore, model data, and enchantments are not rewritten or filled in; legacy forms are no longer silently patched or upgraded automatically.
  • Legacy forms in the other modules can still be handled with each module's one-shot command (confirm in preview mode first, then add confirm to apply): /emakiforge convert-legacy, /emakigem convert-legacy, /emakistrengthen convert-legacy, /emakilevel convert-legacy, /emakicooking convert-legacy. The converters are migration utilities rather than plugin features; see the legacy config converter retirement list for the full retirement list.
  • For production upgrades, back up the full configuration directory first.

CoreLib boundary change: domain protocols moved back to business modules ​

CoreLib no longer owns domain protocols and extension points. Use the current owners:

  • The item layer preview SPI (ItemLayerPreviewProvider, ItemLayerPreviewRequest, and related types) was removed from CoreLib and is now owned by EmakiItemApi in emaki.jiuwu.craft.item.api.preview.
  • Equipment skill PDC keys and their codec are now owned solely by emaki.jiuwu.craft.skills.api.pdc.EquipmentSkillPdcCodec in EmakiSkillsApi.
  • The attribute PDC and attribute service contract is now authoritative in EmakiAttributeApi (emaki.jiuwu.craft.attribute.api.PdcAttributeAccess with the full PdcAttributePayload), reached through EmakiAttributeApi.extensions().pdc().
  • All CoreLib compatibility adapters were removed in CoreLib 4.6.7: SkillPdcGateway, PdcAttributeGateway, and the mirror types PdcAttributeApi, PdcAttributePayloadSnapshot, and EmakiAttributeBridge no longer exist. External code still referencing them will throw NoClassDefFoundError.

Documentation update highlights (2026-09-18) ​

This round re-verified the documentation against the current source, POMs, default resources, and descriptors. The main changes are:

  • Version line sync: module versions, Jar file names, Maven/Gradle coordinates, and config.yml / lang/*.yml resource versions for all 14 runtime/API modules are aligned with the current POMs; the module version tables in the README and the documentation site were updated as well.
  • Repository structure: the default reactor has 23 modules (14 API + 9 runtime); the private-modules profile adds 5 more runtime modules (Skills, Gem, Item, Storage, Accessory), for 28 in total when enabled. Module counts and profile membership in the README and the getting-started pages were corrected against pom.xml.
  • CoreLib numeric actions: added the take_food section; the health, food, experience, currency, and item-count sections now validate explicitly (negative and non-finite values return INVALID_CONFIG instead of being silently clamped); an insufficient deduction returns REJECTED with no partial deduction; added documentation for the action.audit audit log.
  • CoreLib animation: documented the api.animation contract and the registerAnimation / playAnimationAsync / stopAnimation / addAnimationListener facades; corrected the incorrect statement that animation definitions need to be replayed after a CoreLib reload — the animation registry survives reloads, and it is the action section table that needs callbacks rebuilt; K-frame examples now use valid pipeline syntax.
  • Item source aliases: added mc to the VANILLA aliases; removed the invalid eco alias under ECOITEMS.
  • EmakiMobs: skills / attributes changed to the current actions / ea_attributes keys (legacy keys fall back with a WARN); added the list / info / kill / count / debug commands and permissions; the public API adds identify, refresh, and the three-argument registerCustomSpawner signature; model.api and model.lod are marked "parsed but not currently effective", and LOD now has near/far tiers; model and action examples use valid pipeline syntax; drain_timeout_seconds is marked as a compatibility-retained entry.
  • EmakiAttribute: documented that & color codes in MythicMobs names are converted to MiniMessage.
  • EmakiAccessory: added the player data file structure (pages.<page>.<slot>) plus v1→v2 automatic upgrade and the refusal to persist unrecognized structures; corrected the skill payload codec class name.
  • Configuration keys and permissions: Level drops the non-existent storage section and pdc.sync_on_*; Station decomposition recipes use item_sources (input_source is the legacy key), tags no longer participate in station binding, and invalid weight values fall back to 1.0; Skills adds cast_mode.enabled and trigger_settings.legacy_dispatch_cancelled_events; corrected the help command permissions for Skills / Storage; Gem removes non-existent placeholders and gem_slot_presentation, clarifies that the gem ID comes from the id field, and adds an item_sources criterion; Forge corrects the material_id fallback order.
  • Retired content removed: the description of legacy configured-item automatic migration was replaced with the retirement notice (see the section above).

Historical sync focus (kept for reference) ​

The following content is from earlier documentation sync rounds and is kept for traceability; parts corrected by this round or already retired are superseded by the sections above and each module page.

Runtime boundary and configuration sync focus ​

  • Platform and scheduling
    • paper-plugin.yml descriptors now declare Paper 1.21.8+ and Folia support. CoreLib provides the Folia scheduler adapter, and business modules route delayed tasks, async work, GUI return-to-main-thread refreshes, and display refreshes through unified scheduling entry points.
    • Requirements now target Paper 1.21.8+ and include the current Folia support declaration.
  • GUI and item presentation
    • GUI slots use item as the current structured item-source field. Dynamic information, confirmation, and preview slots prefer template item, display_name, lore, and component settings.
    • EmakiGem inlay/open/upgrade GUIs no longer auto-fill the target item from the player's main hand or inventory when opened. Players must place target equipment and materials manually.
    • EmakiSkills skill panels, trigger selection, and EmakiStrengthen preview/confirmation dynamic slots now follow the same template-first GUI rule.
  • Attributes and PDC
    • Attribute supports ranged random values. Lore/PDC parsing can represent percentage and integer ranges, and snapshots keep minimum, maximum, and resolved values for ranged contributions.
    • variables and ea_attributes are separated more strictly: variables are text/placeholder context, while real attribute output should use explicit ea_attributes.
    • Recent cleanup removed ea_attribute_meta logic; materials, gems, items, and strengthen configs should not rely on it as the current attribute metadata entry.
  • Cooking recipes
    • Recipe results now use the unified result.<branch>.outputs/actions structure. Success, early, over, undercooked, overcooked, and invalid branches follow the same model.
    • Recipe completion conditions were added, and station interaction keys were adjusted to the current source behavior.
    • Station floating text, display backend, and refresh configuration are part of the current configuration line.
  • Level
    • Added the EmakiLevel / EmakiLevelApi module for multiple level types, exp sources, requirements, PDC, PlaceholderAPI, CoreLib actions, MythicMobs drops, and EmakiAttribute contribution bridging.
    • VitePress now includes detailed Level module documentation, and the getting-started, introduction, and architecture pages include the progression module.
  • Forge / Gem / Strengthen / Item / Skills
    • Forge material effects show only payload fields for the selected effect type. quality_modify uses tier, and capacity_bonus uses value.
    • Gem items are refreshed from the current gem definition when obtained, after reloads, and when reconstructed inside GUIs.
    • Skills, Strengthen, Forge, Gem, and Item use the es_skills list form for skill effects in current examples and documentation.

    • Scaling curve documentation for logarithmic, sqrt, and piecewise_linear rules.

    • Station documentation for display entities, display distance, refresh interval, wok animation, and scald damage.
  • Forge

  • Strengthen
    • Branch tree documentation for branch recipe files and transfer design notes.
  • Item

Removed or corrected ​

  • Gem commands
    • Removed old admin entries that are not in the current command router.
    • Current command set: /emakigem gui <inlay|open|upgrade>, reload, inspect, clearstate, and debug.
    • Current permissions: emakigem.use, emakigem.reload, emakigem.admin, and emakigem.debug.
  • Skills commands

    • Old trigger management commands were removed.

Recommended reading order ​

  1. Read the target module overview page to confirm responsibilities and dependencies.
  2. Read commands and permissions before configuring permission groups.
  3. Read configuration directory or core feature pages to understand default files.
  4. Read feature-specific pages such as socket openers, skill triggers, attribute scaling, forge quality, or cooking stations.
  5. After editing configuration, verify with the module's reload, inspect, debug, or lint command if available.
  6. Before upgrading a live server, test with real equipment and player data on a staging server.

Upgrade checklist ​

  • Back up all plugins/Emaki*/ configuration directories.
  • Back up player data, equipment data, Cooking station data, Station queue data, Accessory data, and economy data.
  • Do not blindly overwrite old configuration files; compare defaults and merge new fields manually. The legacy configured-item automatic migration has been retired, legacy item definitions are not converted on startup, and they must be migrated by hand to the canonical item.source / item.amount / item.components structure.
  • Check whether commands and permission nodes match the current documentation.
  • Check whether Attribute hard_lock_damage and environmental damage mapping fit your server.
  • Check whether Gem has merged socket_openers, inlay_success, and global upgrade configuration.
  • Check whether Skills has merged actionbar, script_engine, and passive_trigger_settings.
  • Check whether Cooking has merged oven, juicer, fermentation barrel station settings, GUI files, and permissions.
  • Check whether Forge quality, history, and condition failure strategies match your gameplay.
  • Check whether Item auto-update and repair configuration affect old items.

Troubleshooting tips ​

  • When configuration fails to load, check the first YAML parse error in the console; the errors after it are usually cascading results.
  • When item attributes look wrong, first confirm whether the CoreLib assembly layer was rebuilt, then check the Attribute PDC output.
  • When a GUI cannot be operated, check permissions, slot configuration, template IDs, and item sources first.
  • When randomized features such as success rates, quality, or strengthen results behave oddly, check formula variables, guarantee counters, and failure handling strategies first.
  • For effects that span modules, troubleshoot in the order CoreLib → Attribute/Skills → business modules.
